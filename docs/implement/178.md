## Ticket understanding

Source manifest: Trello card (ready, read in full); repo docs `docs/DEPLOY.md`, `docs/knowledge-base/area/ssr-seo-and-prerender.md` (ready). No design, no chat thread.

The API (BE PR #60) limits `/public/*` per visitor IP (60/min, 2,000/day). Server renders call `/public/*` from the server's IP for every visitor, so the limit stays off until server-side `/public` calls carry `X-SSR-Secret` (from `SSR_SHARED_SECRET`) and `X-SSR-Client-IP` (the visitor, from a header the visitor cannot set). Browser calls stay unchanged. The secret must never reach the browser. A rate-limited SSR call must fail gracefully and not be cached into the page.

**Finding: there is no deploy platform yet.** No deploy config in the repo. `https://hostelhive.com` answers `Server: DPS/2.0.0` with a GoDaddy CSP (GoDaddy Website Builder); `hostelhive.pk` does not resolve. So no platform client-IP header could be chosen.

## Plan

The planning here was done by the orchestrator, without the PE/PM agents: the change is two small files plus wiring, and the open questions were product/deploy questions for the user.

- `server.ts`: `app.set('trust proxy', SSR_TRUST_PROXY)`; read `SSR_SHARED_SECRET`; pass `{ ssrSecret, clientIp: req.ip }` to `angularApp.handle(req, context)` (`REQUEST_CONTEXT`).
- `ssrApiHeadersInterceptor`: reads `REQUEST_CONTEXT` (null in browser and prerender), adds both headers to `${baseUrl}/public/*` only; a 429 calls `SsrResponse.serviceUnavailable()`.
- Specs for the interceptor, for IP resolution against real Express, and a source scan that keeps the env name in `server.ts`.

## Decisions

| Question | Decision | By |
|---|---|---|
| Where the visitor IP comes from, with no platform chosen | Express `trust proxy` hop count from `SSR_TRUST_PROXY` (default 0), counting `X-Forwarded-For` from the right. Not the leftmost entry the card mentions, which the visitor writes | user (recommended option) |
| What a 429 on an SSR `/public` call does | Page answers 503 + `Retry-After` + `no-store`, on every public page | user (recommended option) |
| Move the card to In Progress | Yes, moved 2026-10-31 | user |
| Where the secret is read | `server.ts` only, passed per request via `REQUEST_CONTEXT` | codebase (keeps the boundary checkable by one spec) |
| Server-only registration vs shared interceptor | Shared, no-op without the context: a second `provideHttpClient` in the server config would drop `withFetch()` and put it after `ssrTimeoutInterceptor` | codebase |
| Headers when the secret is unset | Neither (the API ignores the IP without the secret) | assumption |
