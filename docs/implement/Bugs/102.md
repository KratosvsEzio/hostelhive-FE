### Ticket (as retrieved)

`app.config.ts` has an initializer marked "DEV ONLY … Remove once login lands" that is not limited to dev builds.
`?role=super-admin|moderator|manager|host` seats a fake session (`id: 'dev'`, token `dev-token`), persists it to the
session cookie (overwriting the real one), and the empty permission list passes every `hasPermission` check. The
backend rejects `dev-token`, so no data loads, but the console screens open and a shared link signs a real user out.

Fix: remove the initializer, or limit it to `isDevMode()`; remove the matching early return in the session-restore
initializer.

Acceptance:
- In a production build, `?role=super-admin` does nothing: no fake session, no console access, real session untouched.
- Login and session restore still work.
- Any dev-only shortcut that is kept is unreachable in a production build.

### Context

- The related backend-URL tester gate is already gone: `feat/mascot-loader` (PR #43) merged into `main` (5ae0e1a);
  `origin/feat/mascot-loader` has no commits ahead of `main`. No conflict risk.
- Login has landed (Lead Wall, Google, invitation, `restoreSession`) — the condition the comment set for removal.
- Nothing else references `?role=`: no e2e spec, no unit spec, no doc beyond a historical line in
  `docs/HostelHive-Implementation-Plan.md:216` (a dated changelog entry; left as history).
- `STAFF` (`app.config.ts:42`) is used only by the dev seed.

### Understanding

A bug: a dev-only convenience shipped unguarded. The fix is subtractive — delete the seed initializer, its `STAFF`
constant and now-unused `SessionStore`/`Role` imports, and the `has('role')` early return so `restoreSession` always
runs on the browser.

## Notes

### Deviation: PE/PM/Staff Engineer agents not spawned

The change is a deletion in one file with a single obvious approach; the two real choices (delete vs gate, test level) went straight to the user. An independent `qa-reviewer` was still run, so the verdict did not rest on the author alone.

### The repo's e2e config reuses whatever is on :4200

`apps/web-e2e/playwright.config.ts` sets `reuseExistingServer: true` for `http://localhost:4200`. On a machine with several worktrees, e2e runs silently test whichever checkout owns that port. Worth a follow-up (e.g. `reuseExistingServer: !!process.env.CI`-style, or a per-worktree port).
