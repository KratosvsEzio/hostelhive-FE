### The ticket

`isUnauthorized(err: unknown): boolean` exists twice as file-private copies — `core/auth/auth.service.ts:250` and `util/favorites-store.ts:285` (added by #105 to skip the reload after a 401). Both read `.status === 401` structurally off the normalised `ApiError`. Fix: export one from `apps/web/src/app/core/errors/` and use it in both places. Acceptance: one definition, both callers import it, `npx nx test web` green.

**Folded in (orchestrator's brief):** `favorites-store.ts:219` still says *"The dev `?role=` seed carries a fake token, so this load 401s there (dev only)."* — #102 removed that seed, so the sentence is now false.

### Sweep (2026-10-11)

- Copies: exactly the two above. No new copies from #114 (`onboarding-draft-store.ts`) or #115 (`host-property-store.ts`).
- `core/interceptors/error-interceptor.ts:42,59` compares `apiError.status === 401` on an already-typed `ApiError` — a different job (branching inside the interceptor), not a copy; left alone.
- `core/errors/` holds `api-error-message.ts` (+ spec), imported as `@core/errors/api-error-message`; it imports only `@hostelhive/data-access`, so a sibling helper there creates no cycle for `util/` or `core/auth/`.

Skipped — not a defect: a duplicated helper, no behaviour to diagnose.

## Plan

4. A small unit spec for the helper; the callers' existing specs (auth restore/sign-in 401 paths, the favourites store's 401 / reload-after-failure tests) are the regression net.

**Phase 2 deviation:** the principal-engineer and product-manager agents were not spawned — a ~15-line refactor with no behaviour change, whose full surface was established by the sweep above. The test-matrix and delivery gates still apply.
