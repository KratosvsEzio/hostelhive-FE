## Ticket understanding

The ticket said: the emailed link `/mess/confirm?token=…` loads the meal from the real API, but Confirm only writes to a mock in-memory list. It asked for a backend endpoint to record the confirmation against the token, and for the page to call it.

### What turned out to be true
- **No email or message links to this page.** The backend developer confirmed that students accept or reject meal confirmations **only from in-app notifications**. Email and WhatsApp carry no confirm action. The template `app/views/user_invite_mailer/meal_confirmation_invitation.html.erb` has no link and tells the student to "log in to the HostelHive app". `pre_requisite_invite_action_service.rb:27` builds a `/meal_confirmation?token=…` URL, but the template never uses it.
- **The real flow already works end to end:** notification bell / `/notifications` → `StudentApi.acceptInvite` → `POST /api/notifications/:id/mark_as_accepted` → `PostRequisiteInviteActionJob` sets `MealConfirmation.is_confirmed` → the host sees it on `/host/…/mess/confirmations` (via `HostelsApi.mealConfirmations`).
- **`/mess/confirm` was an orphan from the early mock design.** Its token lookup (`GET /public/meal_confirmations/meal_info/:token`) does not exist on any backend branch, so every token rendered "invalid". Its Confirm wrote to `MessNotificationsService`'s seeded signal, which nothing else read.

## Root cause

**Confirmed.**

| | |
|---|---|
| **Symptom** | `/mess/confirm` showed "Confirmed" while nothing was saved |
| **Cause** | The page was built against a mock opt-in design (token codec plus in-memory list in `mess-notifications.service.ts`) that the backend never adopted. The backend confirms only through notifications |
| **Why it escaped** | The page had no spec. Nobody checked the frontend's assumed contract (`meal_info`, a public confirm, an emailed link) against the backend's routes or the email template. A 404 from `meal_info` was caught and shown as "invalid", so the page looked like it worked |
| **Same shape elsewhere?** | The host's mess notification settings still offer WhatsApp and SMS channels; whether the backend sends those is unverified. Left as a separate question, not changed here |
