### The ticket

#166 moved the room calendar and the tenant availability check onto the hostel's date (`todayIn(zone, now)`, zone from `HostPropertyStore.timeZoneOf(hostelId)`, cached per session including null). Four places still take "today" from the device, so a host whose device is in another zone sees them a day off around hostel midnight:

| Where | Code @ 826d9aa | Effect |
|---|---|---|
| Bookings calendar | `features/host/bookings/booking-calendar.ts:113` (`today = new Date()`, also `:117`, `:150`, `:165-166`), `booking-month.ts:208` (`today: Date = new Date()` default) | today highlight, opening month, default selected day |
| Booking form | `features/host/bookings/booking-form-drawer/booking-form-drawer.ts:101` (`checkIn = signal(isoDay(new Date()))`) | default check-in |
| Overview strip | `features/host/overview/overview.ts:141` (`stripRange(new Date())`), `:157` (`upcomingStrip(…, new Date())`) | the strip's first day |
| Tenant leave confirm | `features/host/tenants/tenant-form-drawer/tenant-form-drawer.ts:159-163` | "N days" from device midnight; `new Date(f.leaveDate)` parses a plain day as UTC (a day off west of UTC whatever the zone) |

**Acceptance:** with device UTC and hostel Asia/Karachi, between 00:00 and 05:00 hostel time the bookings calendar's today cell and opening month, the booking form's default check-in and the overview strip's first day are the hostel's date; the leave count is right west of UTC and for a device in another zone; same-zone hosts unchanged; specs pin each through the hostel zone, east and west.

### What we already decided in this area (from #166 and the KB)

- `todayIn` falls back to the device date for a missing/unknown zone; never throws. The zone is one cached `GET /api/host/hostels/:id` per hostel per session, null included (D1, D11).
- Read the clock once; gate the view on the zone so the first paint doesn't jump; no midnight timer (D7).
- No visible "hostel time" cue (D2).
- Specs: `Date.UTC` instants with `Pacific/Kiritimati` / `Pacific/Pago_Pago`; Node on Windows ignores an IANA `TZ` at startup, so a west-of-UTC device run needs a `--require` preload that sets `process.env.TZ`.
- The overview strip's comment says it is "rebuilt from `new Date()` on every read so the strip cannot outlive midnight" — a deliberate live-clock choice that conflicts with read-once; to settle in 2d.

## Root cause

**Status:** confirmed (Phase 5: regression specs fail on the pre-fix code on Karachi, UTC, America/New_York and Europe/London, and pass after).

| | |
|---|---|
| **Symptom** | Device on UTC, hostel Asia/Karachi, 00:00–05:00 Karachi: the bookings calendar highlights yesterday (and opens on the previous month on the 1st), the ledger defaults to yesterday, the booking form defaults to yesterday → today, the overview strip starts yesterday, the leave count is one too many. West of UTC a plain-day leave date counts one short in any zone. |
| **Cause** | Each site builds "today" from the device calendar: `booking-calendar.ts:113` (+`:116-118`, `:150`, `:161-169`), `booking-month.ts:208` default, `booking-form-drawer.ts:101` **and `:102-104` (check-out = device now + 24 h)**, `overview.ts:141` and `:157` (two separate clock reads), `tenant-form-drawer.ts:159-163` (device midnight; `new Date('yyyy-MM-dd')` parses as UTC; `Math.ceil(ms/86400000)` miscounts across a DST fall-back). |
| **Why it escaped** | Each site has its own local-`yyyy-MM-dd` helper (`isoDay`, `isoDate`, `ymd`, `localDay`) written to dodge `toISOString()`'s UTC trap, which silently assumes device = hostel. Before #166 there was no "hostel today" source; #166 added `todayIn` + `timeZoneOf` and moved one consumer. No spec pins these with a fixed instant and an explicit zone (`booking-calendar.spec.ts:8` reads the real clock; nothing tests `leaveInfo`; no overview component spec); the dev machine is Karachi. |
| **Same shape elsewhere?** | Yes — form defaults and filters in expenses (`expenses-list.ts:87` `[max]`), invoices (`invoice-form.model.ts:30`), utilities (`add-bill.ts:90-112`, `utilities.ts:119`), mess (`add-grocery.ts:53`, `mess-confirmations.ts:32,101`, `mess-notifications.ts:115`, `mess.service.ts:125`), staff (`staff-form.model.ts:87`), tenant joining time (`tenant-form.model.ts:98`), and both date-range pickers (`lib/src/ui/lib/date-range-picker/date-range-picker.ts:83,444`, `layout/components/date-range-picker/date-range-picker.ts:23`). Follow-up card. |

**Worse symptom, code-proven (be-hostelhive `main` 38ff508, `app/models/booking.rb:35,233-235`):** `validate :checkin_not_in_past, on: :create` rejects `checkin_date < hostel.time_zone.now.beginning_of_day`. So for a device behind the hostel, the booking form's **default** check-in (the device's yesterday) is refused on save as "cannot be in the past" — mapped by the FE to `checkInCannotBeInPast`. Not reproduced live.

## Plan

**Merged plan (PE change list checked against the PM's 29 ACs):**
- **T0 shared:** new `util/plain-day.ts` — `dayPart`, `calendarDaysBetween` (signed, via `Date.UTC` on the parts, DST-proof), `addDays`, `dayToLocalDate`.
- **T1 bookings calendar:** `BookingCalendar` injects `HostPropertyStore` and reads the zone itself (no `bookings.ts`/`.html` change — #175's files); clock read once (`openedAt`), `today` computed, `offset` signal with `monthStart` derived (room-calendar pattern); fetch and month label gated while the zone is pending (existing skeleton); `buildBookingMonth` takes a required `today: string`.
- **T2 booking form:** injects the store; defaults derived from `todayIn(zone, openedAt)`, check-out = check-in + 1 calendar day; `userRange` set only by `onRangePicked`, so a late zone moves an untouched default and never an edit; date-field skeleton while pending.
- **T3 overview strip:** zone inside the `upcomingResp` pipe; one `today` per fetch carried with the response, used for both the range and the cells; the wrong "rebuilt on every read" comment removed.
- **T4 leave count:** pure `leaveCountdown(leaveDate, today)` in `tenant-form.model.ts` using `calendarDaysBetween(today, dayPart(leave))`; the drawer asks the zone lazily (only once a leave date is entered on a new tenant — monthly hostels then make one cached zone request); falls back to the device date while pending.
- **T5 KB:** fix the stale #166 decision line (null *is* cached since D11), record the store-inside-child deviation and the monthly-hostel zone request, update the dates-area trap.
