### The cards

- **#131:** `Seo.apply` (`core/seo.ts`) always writes `<link rel="canonical">` with `path ?? '/'`, so every `noindex` page without a `path` canonicalises to the home page. That covers filtered/uncurated/worldwide searches (`search-map.ts`), the blog-article not-found branch, the place-landing not-found branch, and listing-detail's noindex branch. **AC:** `/en/search?gender=girls` has `noindex` and no canonical; an unfiltered curated search still canonicalises to `/hostels/<slug>`; indexable pages keep their canonical.
- **#127:** JSON-LD set and never cleared on destroy:
  - home: `organization`, `website` (`home.ts:92,106`);
  - blog: `blog` (`blog.ts:180`);
  - blog article: `article`, `breadcrumb` (`blog-article.ts:225,248`);
  - listing: `listing` (`listing-detail.ts:1143`), plus the preload image link (`:994`).

  **AC:** a client navigation away from each leaves none of its ids; each page's server HTML still contains its blocks.

### What we already decided in this area

- **#121 (PR #86):** `PlaceLanding` clears its JSON-LD in `DestroyRef.onDestroy`. Verified SSR-safe: `@angular/ssr` serialises the document before destroying the platform (`ssr.mjs:181-207`). A raw-HTML e2e test guards it (`search-new-place-and-landing-head.spec.ts`).
- `Seo.setAlternates` already emits **no hreflang for `noindex`**, because alternates "advertise a page for indexing, which directly contradicts" `noindex` (`seo.ts`). The canonical never got the same treatment.
- The decision `curated-landing-pages-own-place-intent.md`: filtered, uncurated or "everywhere" searches are `noindex` with **no** canonical.

## Root cause

**Status: symptoms reproduced on `main`; the cause is hypothesised** until a test fails before the fix and passes after.

| | |
|---|---|
| **Symptom** | #131: `noindex` pages server-render `canonical https://hostelhive.com/en`. #127: home's `organization`/`website` follow the visitor to the blog, and the blog's `blog` follows them back. |
| **Cause** | **#131:** `seo.ts:77` defaults `path` to `'/'`; `:95` writes the canonical, and `:101` `og:url`, whatever `noindex` says. `noindex` was taught to robots and hreflang (`:86`, `:135`) but never to the canonical or `og:url`. The rule lived only at a caller comment (`search-map.ts:870-871`) and in the KB decision. Also, the head starts from a static home canonical and `og:url` (`apps/web/src/index.html:24,33`), so **not writing is not removing**: the fix must delete the link and tag. (The reproduced href `/en` is `withLocale('en','/')`, so `apply` is the writer, not the static tag.) **#127:** home (`home.ts:92,106`), blog (`blog.ts:180`), blog-article (`:225,248`) and listing (`:1143`, preload `:994`) set per-page-type JSON-LD ids and never clear them on destroy. `Seo`'s "overwrite by id" model only works when the same component is reused. |
| **Why it escaped** | No `core/seo.spec.ts`. `search-map.spec.ts` checks the caller contract ("no `path`") with a `Seo` spy and trusts `Seo` to turn that into "no canonical". JSON-LD has only been checked in server renders (a fresh document per request). `home.spec.ts` stubs `Seo`; blog, blog-article and listing have no component spec. The right levels are a unit test of the real `Seo` and a component destroy spec with the real `Seo`, plus one client-navigation e2e. |
| **Same shape elsewhere?** | `og:url` (same default, so noindex share cards point at home; Facebook and LinkedIn re-scrape it). Pages that never call `apply` keep index.html's home canonical and `og:url` (= #129, out of scope). `og:locale` is a static `en_PK`. **Blog calls `apply` in its constructor**, so a client language switch keeps the `/en/blog` canonical on `/ur/blog`. No id is shared between page types. No page component is destroyed during a server render (no `@if` around the outlet, no `@defer` page, no resolvers, a navigation mid-render becomes a redirect), so serialise-before-destroy holds for all four pages. |

## Plan

### Merged plan
1. **`Seo.apply` encodes the rule:**
   - remove the `'/'` default;
   - `url = path ? origin + withLocale(active, path) : null`;
   - the canonical is written only when **not `noindex` and `url` is set**, and otherwise the existing link is **removed** (`setCanonical(null)`);
   - hreflang is unchanged (none for `noindex`);
   - `og:url` is written when `url` is set and otherwise removed.
2. **`Seo.clearOnDestroy(destroyRef, ids, { preloadImage? })`:** the SSR-safety and order explanation lives once in `seo.ts`. It is used by home (`organization`, `website`), blog (`blog`), blog-article (`article`, `breadcrumb`) and listing (`listing` + preload), and PlaceLanding is migrated to it (D-pending).
3. **Ripples:**
   - the `Seo` stub in `home.spec.ts` gains `clearOnDestroy`;
   - **`search-new-place-and-landing-head.spec.ts:81-82` will break**: the Karachi search correctly has no canonical after the fix, so it gets rewritten to assert absence, not weakened.
4. **Not touched:** `index.html`'s static tags and pages without `apply` (#129).
5. **Tests:**
   - a new `core/seo.spec.ts` (real `Seo`: a seeded static canonical is removed, noindex↔index both ways, path rules, `clearOnDestroy`);
   - new `blog.spec.ts` and `blog-article.spec.ts` destroy/reuse specs;
   - a new e2e for server raw HTML (noindex: no canonical or `og:url`; indexable pages keep theirs; each page's JSON-LD present) and client navigation (each page's ids gone after leaving; noindex → index recreates the canonical; listing via a stubbed `hostel_detail` if workable).

### Principal Engineer report (key content)
- **SSR order:** `@angular/ssr` 21.2.7 `renderAngular` waits for `whenStable`, serialises, then destroys on `setTimeout(0)`; prerender uses the same path.
- **Reuse:**
  - `/blog/a` → `/blog/b` and `/hostel/a` → `/hostel/b` reuse the component (the effects overwrite);
  - a locale switch reuses it;
  - a different config destroys the old component before creating the new one.
- **Edge cases:**
  - noindex → index recreates the canonical and `og:url`; the reverse removes them;
  - noindex with a path: no canonical, `og:url` from the path;
  - an indexable page without a path: no canonical, no `og:url` (none exist);
  - the listing's loading state briefly removes its canonical client-side (harmless).
- **Risks:**
  - the e2e at `:81-82` breaks (certain);
  - the listing e2e relies on a client refetch after a 5 s SSR timeout (slow);
  - server-render e2e for search waits on the API (5 s cap);
  - delete the temporary repro spec and config before lint.
- **Decomposition:** T1 `Seo` + spec → T2 pages + specs → T3 e2e → T4 KB. About 60 production lines, so one engineer, sequential.
- **Open questions:**
  1. noindex with a path: no canonical (yes);
  2. `og:url` without a path: drop it (yes);
  3. remove the `'/'` default (yes);
  4. the helper plus migrating PlaceLanding (yes);
  5. index.html's static tags: no (#129);
  6. follow-ups for Blog's stale canonical on a language switch and the static `og:locale`.

### Product Manager report (key content)
- **Impact:**
  - #131 is moderate SEO hygiene: thousands of facet URLs claim to duplicate `/en`, which costs crawl effort and adds Search Console noise. **The most visible harm** is Facebook and LinkedIn link previews using `og:url` = home for shared filtered searches and dead listings.
  - #127 matters for rendering crawlers and preview tools after in-app navigation.
- **ACs 1–33:**

- **Risks:** SEO regression on indexable pages (the SSR matrix guards it); the index.html static tags (only a raw-HTML test catches it); the `:81` e2e; listing checks need stubbed data.

## Summary

**#131 is fixed.** A noindex page no longer canonicalises to home:
- `Seo.apply` writes no canonical for noindex and no hreflang;
- it writes an `og:url` only when the page has a path;
- it **removes** index.html's static canonical and `og:url` rather than leaving them;
- the `'/'` default is gone.

Indexable pages keep exactly one canonical, a matching `og:url` and the full hreflang set.

**#127 is fixed.** Home, blog, blog article and listing now clear their JSON-LD ids, and listing also its preload, when they are destroyed. They use the new `Seo.clearOnDestroy`, which PlaceLanding also uses now. The server HTML still carries every page's blocks.

**Tests:**
- 11 unit, 7 component and 7 e2e cases, plus the D8 rewrite;
- every bug-fixing case fails on main;
- guard cases protect the behaviour that must not change;
- full unit run 2216/2216 (round 1); e2e lane 32/32.

**Not covered:**
- the listing page end to end (E7 dropped; manual M1 needs the live API);
- a click made before the client boots (residual, below);
- #132 and #133, which were filed separately.

**Knowledge base (6b), drafted for after the merge:**
- `area/ssr-seo-and-prerender.md` gets a "Head tags" section:
  - canonical only on indexable pages with a path;
  - `og:url` only with a path;
  - the static index.html tags are removed, not left;
  - `clearOnDestroy` for any page writing JSON-LD;
  - the trap that a click before boot strands server blocks.
- The `search-and-discovery.md` SEO line gets "noindex → no canonical".

**Residual, outside this fix:** a click made before the client boots leaves the server page's JSON-LD in the head. The router replaces the first navigation before the page component exists in the browser, so `clearOnDestroy` never runs. This is no regression: on main, nothing cleared those blocks at all. Crawlers do not click, so the SEO impact is low. The candidate fix is a follow-up card: in the browser only, remove any server-rendered `script[data-seo]` that no component claimed after the first navigation.
