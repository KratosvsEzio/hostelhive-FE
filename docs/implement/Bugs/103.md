### Ticket text (summary)

Since PR #30 every URL carries a language prefix. `apps/web/public/robots.txt` lists only bare paths
(`/host$`, `/host/`, `/admin`, `/moderator`, `/forbidden`, `/account`, `/notifications`, `/auth`,
`/mess/confirm`), and robots rules match on prefix, so none of them match `/en/account`, `/ur/auth?…`,
`/xx/mess/confirm?token=…`. Fix: add a prefixed rule per path; keep the warning about bare `/host`
(must not block `/xx/hostel/…` or `/xx/hostels/…`); keep the bare rules.

Acceptance:
- `/en/account`, `/de/auth`, `/en/mess/confirm?token=x`, `/en/host/abc/overview` blocked.
- `/en/hostel/<slug>`, `/en/hostels/lahore`, `/en/search` allowed.

### What we already decided in this area

- Authenticated areas render client-only in every locale shape — `clientOnly()` in
  `apps/web/src/app/app.routes.server.ts` (commit `2b679d6`) fixed the same bug for render modes.
- The sitemap is generated by the SSR server from route data so it cannot drift (`server.ts`).
- `sitemap-urls.spec.ts` already asserts the sitemap excludes the robots-blocked prefixes, but checks
  bare prefixes only.

## Root cause

**Confirmed** (Phase 5): the same matcher run over the old static file reported `/en/account`, `/de/auth`, `/en/mess/confirm?token=x` and `/en/host/abc/overview` as **allowed**, and only bare `/account`, `/host/x` as blocked.

| | |
|---|---|
| **Symptom** | Crawlers may index `/xx/account`, `/xx/auth`, the consoles' empty shells and `/xx/mess/confirm?token=…` |
| **Cause** | `apps/web/public/robots.txt` was hand-written with bare paths before PR #30 (fbe7625) prefixed every URL with a language; nothing tied it to `LOCALE_CODES` |
| **Why it escaped** | No test evaluated robots.txt against a real URL. `sitemap-urls.spec.ts` checked the sitemap against hard-coded *bare* prefixes, so it agreed with the stale file |
| **Same shape elsewhere?** | Yes, the server render-mode table (`app.routes.server.ts`, fixed in `2b679d6`). Also `/confirm_invitation` and `/reset_password` carry tokens and were never disallowed at all |

## Plan

`/sitemap.xml` already is. Delete the static file. Add `confirm_invitation` and `reset_password`.

## Notes

### Why the ticket's `/*/path` suggestion is not enough

In robots.txt `*` matches any run of characters **including `/`**, unlike Angular's single-segment
`*`. So `Disallow: /*/auth` also blocks `/en/blog/authentic-…`, `/en/hostel/admin-…` style slugs, any
future public path whose later segment starts with a blocked word. No current slug collides (136 slugs
checked 2026-10-10), but the guard would be by luck. Rules naming each locale (`/en/auth`, `/ur/auth`, …)
match only the real shape.
