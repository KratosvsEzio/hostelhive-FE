### The ticket

`room-calendar.ts` `today()` uses the device's date. Since #83 (D17) that date also decides when a checked-out stay stops holding beds (`room-stays.ts` `nightsHeldUntil`), besides the today highlight and the roster's default day. A host on a device in another zone sees the wrong "today" and wrong free beds around midnight hostel time. The calendar only receives `hostelId`.

**Fix direction:** pass the hostel's time zone (`Hostel.timezone`, since #81) into the room calendar and compute "today" with the zoned-time helpers. Use the same for the tenant form's availability check, which calls `toRoomMonth` with the default.

**Acceptance:**
- With the device in a different zone from the hostel (e.g. device UTC, hostel Asia/Karachi), around midnight the today cell, the roster default day and the checked-out cut-off follow the hostel's date.
- Specs pin "today" through the hostel time zone, not the device clock.

### What the code shows

- `room-calendar.ts:94` `today()` = device date; used for `toRoomMonth(…, today())` (`:244`), the `isToday` cell (`:354`/`:409`) and the roster default (`:449`).
- `room-calendar.ts:169` `openedOn = new Date()` decides the month the calendar opens on — also device-local, not named by the card.
- `room-stays.ts:89-93` `localToday()` is the default `today` for `toRoomStay`/`toRoomMonth`; callers that pass nothing (`tenant-form-drawer.ts:260`) get the device date.
- `tenant-form-drawer.ts:159` has its own device-midnight `today` for a day-count.
- Inputs: `RoomCalendar` takes `hostelId`, `roomId`, `capacity`, `residents` — no zone. Where the host console can read the hostel's zone is the open question for Phase 2.

## Root cause

**Status:** confirmed (Phase 5: the regression specs fail on the pre-fix code and pass after, on Asia/Karachi and UTC).

|---|---|
| **Symptom** | With the host's device in a different zone from the hostel, around hostel midnight the today cell, the roster's default day and the free beds left by checked-out stays are a day off; near a month end the calendar opens on the wrong month. |
| **Cause** | `room-calendar.ts:94-96` `today()` and `room-stays.ts:92-96` `localToday()` read the device clock; `room-calendar.ts:169` bases the opening month on it. | **Why it escaped** | A pure unit spec with a fixed instant and an explicit zone would catch it; none exists. ## Plan

**Merged plan (PE change list checked against PM acceptance):**
1. `util/zoned-time.ts` gains `todayIn(zone, now = new Date())`: `yyyy-MM-dd` on `zone`'s wall calendar via `Intl.DateTimeFormat(...).formatToParts`; device-local date when the zone is missing or `!isKnownTimeZone`; never throws.
2. Zone source without a backend change: `HostShellApi.hostelTimeZone(id)` → `GET /api/host/hostels/:id`, reads `hostel.timezone`, toast suppressed, errors → `null`; `HostPropertyStore.timeZoneOf(id)` caches per hostel per session (cleared in `clear()`/`syncOwner()`); stub in `testing/host-stubs.ts` defaults to `of(null)`.
3. `room-stays.ts`: delete `localToday`; `today` becomes required (options object) so no caller silently gets the device date.
4. `room-calendar.ts`: `timeZone` input; clock read once (`openedAt`); one `today` computed feeds the today cell, roster default, D17 cut-off and the opening month; `today` joins the fetch key.
5. `room-detail`: reads the zone from the store, gates the calendar until it settles (no first-paint jump), passes `[timeZone]`.
6. `tenant-form-drawer.ts:260`: nightly path adds the zone to its `forkJoin` and passes `today: todayIn(zone)`.
7. Specs: fixed `Date.UTC` instants with zones east and west (including Pacific/Kiritimati vs Pacific/Pago_Pago); `room-stays.spec.ts` gets explicit `TODAY` everywhere.
8. KB in the same PR: fix "today is the device's date" in `room-occupancy-counts-per-room-occupancies.md`, `zoned-time.ts` gains its first importer in the dates decision, and a decision for "the console's today is the hostel's".
