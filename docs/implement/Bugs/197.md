**The ticket (card text, condensed).**
- **Part 1, a product call.** Each of the 16 blog articles is served at all 18 language URLs. Each is self-canonical, with the full hreflang set and 18 sitemap entries (`blog-article.ts` `Seo.apply({ path: /blog/<slug> })`). But the body is English: `lang="en"` in `blog-article.html`, and `inLanguage: 'en'` in the JSON-LD.
  - **Option A:** treat articles like the legal pages (canonical `/en/blog/<slug>`, no hreflang, English-only sitemap entries; the chrome stays translated).
  - **Option B:** keep the current behaviour and record why.
- **Part 2, a defect under either option.** The article JSON-LD `url`/`mainEntityOfPage` (`blog-article.ts:218`, `:251`) and the breadcrumb (`:268`, `${SITE_ORIGIN}/blog`) are unprefixed. Those URLs redirect (`keepLocale`) and disagree with the canonical.
- **Acceptance:**
  - the product decision is recorded;
  - under A: canonical `/en/blog/<slug>` on every language, no hreflang, English-only sitemap entries;
  - JSON-LD URLs equal the canonical URLs, with a language prefix;
  - specs cover both.

**Found while reading (same shape, not on the card).** The blog index JSON-LD (`blog.ts:199-212`) also writes an unprefixed `url` (`${SITE_ORIGIN}/blog`) and unprefixed per-post URLs.

**What we already decided in this area:**
- #139 D1: route data `contentLocale` → `SeoConfig.contentLocale`, with `SINGLE_LANGUAGE_PAGES` driving the sitemap.
- #139 D2: canonical only — no `noindex`, no robots rule.
- #139 D3: `<html lang>` follows the URL; the content is wrapped in `lang="en"`.
- #139 D4: `og:locale` is the content locale.
- #139 D8: titles stay translated.
- #139 D9: blog articles deferred to this card.
- `blog.ts:46-62`: the blog index's chrome is deliberately translated; headlines and prose stay English.
- `Seo.apply` already supports `contentLocale` (`core/seo.ts`).

## Root cause

**Status:** code-proven. `blog-article.spec.ts:236,263,272` assert the current self-canonical and unprefixed values; confirmation comes in Phase 5 (fails before the fix, passes after).

| | |
|---|---|
| **Symptom** | `/ur/blog/<slug>` claims an Urdu article exists: it names itself canonical, writes 19 hreflang and `og:locale ur_PK`, and is listed in the sitemap in 18 languages. Its JSON-LD `url`, `mainEntityOfPage` and breadcrumb point at `/blog/…`, a redirect that matches neither the canonical nor `og:url`. |
| **Cause 1** | `blog-article.ts:233-240` passes no `contentLocale`, so `seo.ts:163-165,185` treats the page as translated. The sitemap repeats the claim because `content-locale.ts:20-25` knows only route-flagged `'index'` pages; a `'page'` route cannot tell the sitemap its language. (#139 D9 deferred this.) |
| **Cause 2** | `blog-article.ts:218,268` and `blog.ts:203,211` build absolute URLs from `SITE_ORIGIN` plus an unprefixed path. The underlying reason: `Seo` builds the page URL privately (`seo.ts:165`) and never exposes it, so pages built a second copy, and only `Seo` learned about locale prefixes (`fbe7625`). |
| **Why it escaped** | The unit specs assert values copied from the code's own output, not the invariant "JSON-LD url equals the canonical". The e2e `headOf` returns only the JSON-LD ids, not their contents (`apps/web-e2e/src/support/seo.ts:52,105`). |
| **Same shape elsewhere** | Unprefixed JSON-LD URLs also appear in `place-landing.ts:265,268,282`, `listing-detail.ts:1112` and `home.ts:116`. English-only content with full hreflang: only the articles. The blog index and place landings are translated where it matters. |

## Plan

**Merged plan (option A, as recommended by both PE and PM):**
1. `Seo.pageUrl(path, contentLocale?)` becomes the only builder of a page's absolute URL, and `apply` uses it for the canonical and `og:url`. JSON-LD authors use it too.
2. `BLOG_CONTENT_LOCALE = 'en'` goes in `blog-post.model.ts`, as the one statement of the archive's language. It feeds `contentLocale`, `inLanguage`, the JSON-LD and the sitemap.
3. Article: the real-post `apply` passes `contentLocale` (the not-found branch does not). JSON-LD `url`/`mainEntityOfPage` = `pageUrl('/blog/<slug>', 'en')`. Breadcrumb = `/en/blog` "Blog" → the canonical.
4. Blog index: its JSON-LD moves from the constructor into the head effect so it follows a language switch. `url` = `/<active>/blog`; each post's `url` = that article's canonical.
5. Sitemap:
   - `pageLocales`/`pageAlternates` take an optional `contentLocale` override, so core never imports a feature.
   - `sitemap-urls.ts` passes the article language, giving one `/en/blog/<slug>` entry each with no `xhtml:link` (288 entries become 16).
6. e2e:
   - drop the article from `INDEXABLE_PAGES`;
   - add an article loop for en/ur/ar;
   - add a language-switch check and an article-to-translated-page check;
   - extend `headOf` to return JSON-LD bodies.
7. KB:
   - the `ssr-seo-and-prerender` area: the `contentLocale` bullet, the sitemap paragraph, the trap, and `pageUrl` under "Reuse, don't rebuild";
   - the single-language decision's consequences;
   - `public-content` notes.

### Principal Engineer report (condensed)
- **Current behaviour:** traced as above. The article effect re-reads `locale.active()` (`blog-article.ts:205`). That read becomes load-bearing once `apply` stops reading `active()` for a valid content locale, so keep it and comment it.
- **Route data `contentLocale` on `blog/:slug` was rejected** for two reasons: the same route serves the translated not-found page, and `app.routes.spec.ts:303-313` requires flagged routes to be `'index'` routes and to equal `SINGLE_LANGUAGE_PAGES`.
- **Rejected for the sitemap:**
  - a per-post language field: 16 copies of `'en'`;
  - deriving from `BLOG_POSTS` in core: core has zero `@features` imports, and it would pull in about 1,400 lines of prose;
  - a `/blog/` prefix rule in core.
- **Rejected for `pageUrl`:**
  - `apply()` returning the URL: it hides the contract;
  - a free function: each page would repeat the "content locale, else active" logic.
- **Decomposition:**
  - T1: shared layer (`seo.ts`, `content-locale.ts`, `blog-post.model.ts`);
  - T2: article;
  - T3: index;
  - T4: sitemap;
  - T5: e2e;
  - T6: KB.

  About 80 production lines in one dependency chain, so **one engineer doing T1→T4 beats a split**.
- **Overlap with #160:** `seo.ts:250-258` doc, `sitemap-urls.ts:17-21` doc, e2e `head-canonical…:12-21,34-55`, KB `:85-112,130-140`. No shared hunks, but adjacent ones, so rebase before delivery.
- **Open questions:** A vs B; a follow-up card for the place-landing/listing/home JSON-LD; breadcrumb name (English under A); `lang="en"` on the category eyebrow (`blog-article.html:36`).

### Product Manager report (condensed)
- **Recommends A.** Google determines language from visible content and ignores `lang` and URLs. Its guidance calls boilerplate-only translation poor practice. On `/ur/blog/<slug>` the title, description, h1, body and even the date are English (DatePipe has no `LOCALE_ID`), so the 18 copies are near-duplicates and the hreflang claim is false.
- **Correction to the brief:** #139 D8 ("title stays translated") does not apply, because article titles are already English everywhere.
- **What A loses:** a searcher in another language lands on `/en` with English chrome, one switch away from their own. Social shares consolidate to one URL.
- **ACs:**
  - AC1–3: head on en/ur/ar/de; html lang follows the URL; body `lang="en"`.
  - AC4–5: sitemap: 16 `/en/` entries with no links; total down 272; new posts covered with no second list.
  - AC6–8: link prefixes, language switch, hreflang restored on leaving.
  - AC9–12: JSON-LD URLs equal the canonical; breadcrumb `/en/blog`; index `url` = its own canonical, with post URLs = article canonicals; no unprefixed URL.
  - AC13–15: guards for not-found, the `/ur/blog` index, and one GA view.
- **Rules:**
  - R1–R3: as #139 D2–D4.
  - R4: not-found unchanged.
  - R5: breadcrumb `/en/blog`, "Blog" in English.
  - R6: the index stays per-language (its h1, lede and controls are translated).
  - R7: new posts are covered automatically.
  - R8: Search Console will move about 272 URLs to "Alternate page with proper canonical tag"; annotate GA with the deploy date.
- **Open questions:** Q1 A/B; Q2 index per-language (yes); Q3 breadcrumb (en); Q4 include the index JSON-LD (yes); Q5 an "English only" note (no, #139 D10); Q6 per-post translation now (no).

### Comment correction (orchestrator, from the 4a reading)

`senior-qa` found that the engineer's "Load-bearing" comment at `blog-article.ts:209-211` overclaims.

**Why:** on the not-found branch `apply` reads `locale.active()` itself (`seo.ts:168`), so the effect re-runs on a language switch even without the explicit read. A real post's head is the same in every language.

**What changed:** the read stays, as a defensive dependency. The comment now says it is tracked so the effect doesn't rely on what `apply` happens to read. This was a comment-only change, so it was made by the orchestrator, not sent back to the engineer.
