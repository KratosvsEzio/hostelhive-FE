### #112 (as written)

> Price sorts are withdrawn while the accommodation type is "Any type", because nightly and monthly prices can't be ordered together: the inline Sort dropdown hides them (`sortOptions` in `search-filters.ts`); since #106, Apply drops a `price-*` sort when the type is "Any type"; the header bar strips it too (`search-bar.ts` `search()`). But the Filters modal (`search-filter-modal.ts`) always offers both price sorts. A seeker who picks "Any type" and "Price: low to high" in the modal sees their sort silently ignored.
>
> **Acceptance:** in the Filters modal, price sorts are unavailable while "Any type" is selected, and a selected price sort is cleared, or explained, when the type switches to "Any type".

### #113 (as written)

> The "Type of stay" buttons in the Filters modal ("Any type", "Boys", "Girls", "Co-living", "Backpacker") are hard-coded English in `search-filter-modal.ts`, so they stay English on `/ur/...` and every other locale while the rest of the modal is translated. Reuse `ACCOMMODATION_LABEL_KEYS` (`util/accommodation-type.ts`) plus a key for "Any type". Note: `search-filters.spec.ts` finds these buttons by their English text, so update it alongside.
>
> **Acceptance:** on `/ur/hostels/lahore`, the modal's type buttons are in Urdu; all locale files carry the keys (`npx nx run web:i18n-check`).

### What the code shows

- `search-filter-modal.ts` holds three hard-coded English option lists: `genders` (type of stay), `ROOM_TYPES` ("Shared room" / "Private room") and `sortOptions` (five sorts). The template prints `{{ g.label }}`, `{{ c.label }}` and `{{ s.label }}` raw.
- **#113 understates the defect.** Room type and Sort in the same modal are English too. Keys already exist for all of them except "Any type":
  - `common.boys`, `common.girls`, `common.coLiving` and `common.backpacker` (through `ACCOMMODATION_LABEL_KEYS`);
  - `search.sharedRoom` and `search.privateRoom` (used by the inline Room type dropdown);
  - `search.recommended`, `search.recentFirst`, `search.oldestFirst`, `search.priceHighToLow` and `search.priceLowToHigh`.
  - Nearest existing key to "Any type": `searchBar.anyAccommodation` ("Any accommodation", used by the header bar). No key reads "Any type".
- **#112:** `sortOptions` is a static array, and nothing reacts to `draftGender`. `SearchFilters.onApply` (`search-filters.ts:252`) later writes `sort: null` for a price sort with type `'all'`, which is the silent drop. `seed()` copies the URL's sort into the draft unchecked.
- Inline filters already handle both cases. `sortOptions` filters out `price-*` when the type is `'all'` (`search-filters.ts:112`), and labels use `t()` = `locale.ready() ? translate(key) : ''` to avoid "Missing translation" warnings before the language file lands.

### Understanding

- **#112:** the modal must stop offering price sorts while its draft type is "Any type". A drafted price sort must not survive into a state where the type is "Any type", because Apply would then drop it silently.
- **#113:** every label in the modal is shown in the active language, and every locale file carries any new key.

Both live in one component and one template, so they are one change.

### What we already decided in this area

- Price sort is withdrawn for "All" because `starting_price` mixes nightly and monthly prices (`search-filters.ts` doc comment; KB area file).
- `onApply` writes a price sort under "Any type" as absent (#106). That stays as defence in depth.
- Labels that live in TypeScript use `t()` gated on `LocaleStore.ready()`, not the pipe and not a bare `translate()` (`search-filters.ts:70-89`).
- i18n-check gates `en.json` only, but the house practice is to add a new key to all 18 files (memory: i18n locale file format; LF in git).

**Assumptions:** none blocking. One question for 2d: "Any type" reuses an existing key or gets a new one, and does the scope extend to Room type and Sort labels.

## Plan

### Merged plan

**One engineer, one task** (the spec, the modal `.ts` and the `.html` carry both tickets, so splitting them would put two agents on the same files).

1. **`apps/web/src/app/features/public/search/search-sort.ts` (new):**
   - `SORT_OPTIONS`: `{ value, key }` in display order. Recommended, Recent first, Oldest first, Price high→low, Price low→high.
   - `isPriceSort(sort)`.
   - `sortsFor(type)`: hides `price-*` for `'all'`.

   This gives the rule one home.
2. **Modal `.ts`:**
   - `genders`, `ROOM_TYPES` and the sorts carry translation **keys**, not English labels. The types use `ACCOMMODATION_LABEL_KEYS`, plus a key for "Any" (see D1).
   - `sortOptions` becomes `computed(() => sortsFor(draftGender()))`.
   - A derived `effectiveSort` reads `'recommended'` while the type is `'all'` and the draft holds a price sort. The pressed state and `apply()` use it. There is no `effect()` and no imperative reset: `seed()` and `clearAll()` are covered by construction (see D2).
3. **Modal `.html`:**
   - `{{ x.key | transloco }}` for all three groups. The pipe, not `t()`: the modal renders its own labels, and `t()` would render empty strings under `provideI18nTesting`.
   - `[attr.aria-pressed]` on the room and sort buttons, matching the type buttons.
4. **`search-filters.ts`:** `allSortOptions` / `sortOptions` are built from `SORT_OPTIONS` / `sortsFor` (still through `t()`, because `hh-dropdown` takes strings). `onApply` uses `isPriceSort` and **keeps its drop as a backstop** (#106).
5. **Ripple (D3):** `search-bar.ts:389` and `search-map.ts:1636` use `isPriceSort`.
6. **i18n:** a new key only if D1 decides one; otherwise none. Every other key already exists in all 18 files.
7. **Specs:**
   - `search-filters.spec.ts` label lookups move to keys (lines 181, 225, 237, 248-249, 270, 284, 302, 337, 353, 365, 380, 392, 405, 429, 442, 451).
   - New cases for what the modal offers, the reset, seeding from a stale URL, and labels rendering as keys.
   - e2e `landing-gender-filter.spec.ts` (and `head-titles.spec.ts:141`) if any English text changes.
8. **KB:** the trap line at `area/search-and-discovery.md:58` is retired in Phase 9.

**Settled without needing the user** (PE and PM agree):
- **Hide** the price sorts, matching the inline dropdown. Disabling helps no one on a touch bottom sheet, and an explanation would need a new sentence in 18 locales.
- **No hint text.**
- **Translate Room type and Sort too**: same sheet, same defect, the keys exist.
