## Ticket understanding

**Source manifest:**

**The ticket (card text, condensed).** Pages build their JSON-LD URLs from `SITE_ORIGIN` plus an unprefixed path. Those URLs redirect (`keepLocale`) and don't match the canonical.

| Location | Problem |
|---|---|
| `place-landing.ts:263` | breadcrumb Home is the bare origin |
| `place-landing.ts:268` | `/hostels/<slug>` |
| `place-landing.ts:282` | `${SITE_ORIGIN}${path}` |
| `listing-detail.ts:1112` | `LodgingBusiness.url` `/hostel/<slug>` |
| `home.ts:116` | SearchAction `/search?place=` |

Two more things:
- The place-landing breadcrumb mixes English literal names (`'Home'`, `` `Hostels in ${p.name}` ``) with a translated third item. That needs a naming decision.
- `home.ts:97,111` uses the bare origin as the Organization/WebSite identity. That is acceptable.

**Acceptance:**
- every JSON-LD URL on SITE_ORIGIN except the identity carries a prefix and equals the matching page's canonical
- the place-landing breadcrumb names are in one language
- specs assert "JSON-LD url equals canonical" on each page

**What we already decided in this area:**
- #197 D5: `Seo.pageUrl(path, contentLocale?)` is the one builder of a page's absolute URL; JSON-LD uses it.
- #197: blog JSON-LD and breadcrumbs describe the English canonical, because the articles are English.
- #139 D3/D8: titles and chrome are translated per language.
- Place landings are translated, per-language, self-canonical pages (`'page'` routes calling `Seo.apply` with `path`).

## Root cause

**Status:** code-proven, and confirmed from git history. A spec asserting "JSON-LD url == canonical" will confirm it in Phase 5.

| | |
|---|---|
| **Symptom** | On `/ur/hostels/lahore`, `/ur/hostel/<id>` and `/ur`, the JSON-LD names unprefixed addresses. They redirect (`keepLocale`; a crawler lands on `/en`) and disagree with the canonical beside them. The place breadcrumb also mixes English literals (`'Home'`, `` `Hostels in ${p.name}` ``) with a translated third item. |
| **Cause** | A page's absolute URL was built in two places. `Seo.apply` builds the canonical; each page built its own JSON-LD URL from `SITE_ORIGIN` plus a path: `place-landing.ts:263,268,282`, `listing-detail.ts:1112`, `home.ts:116`. |
| **Why it happened** | The blocks were written on 2026-08-17 (`a9871a7`, `e2fccf0`), when English had no prefix. `fbe7625` (2026-08-22, "give every URL a language") changed `seo.ts` and `keep-locale.ts` but not these pages. #197 added `pageUrl` and adopted it on the blog only (D9). |
| **Why it escaped** | `place-landing.spec.ts` and `home.spec.ts` only count blocks. `listing-detail.spec.ts` asserts the canonical but never the JSON-LD. The e2e `JSON_LD_PAGES` checks ids only; bodies are checked for the blog alone. A component-level invariant spec would have caught it. |
| **Same shape elsewhere** | `listing-detail.ts:573`: the WhatsApp message link uses `location.origin`, unprefixed. It is a human link, so not SEO. Asset URLs (images, logo, social images) are correctly unprefixed. hreflang, the sitemap and robots are correct. |

## Plan

**Merged plan (single engineer; there is no shared layer, because `pageUrl` exists):**

1. **Place landing (`place-landing.ts:259-287`).**
   - Item 1 = `pageUrl('/')` named `publicLanding.home`.
   - Item 2 = `pageUrl('/hostels/<slug>')` named `publicLanding.hostelsIn {place}`. These are the same keys as the visible breadcrumb, present in all 18 locales.
   - Item 3 = `pageUrl(path)`, keeping its translated name.
   - Drop the unused `SITE_ORIGIN` import. The block is already written from the ready-gated effect, so it follows a language switch.
2. **Listing (`listing-detail.ts:1093-1112`).**
   - Build `path = '/hostel/' + l.slug` once, and use it for both `apply({path})` and `url: pageUrl(path)`.
   - `slug` is the sqid id, typed `string`, so a null slug cannot happen.
   - Drop the `SITE_ORIGIN` import.
3. **Home (`home.ts:104-121`).**
   - The `website` block moves into its own effect with no `ready()` gate. It holds no strings, and gating it would break `home.spec.ts:420-433`.
   - `urlTemplate` = `pageUrl('/search') + '?place={search_term_string}'`.
   - The `Organization`/`WebSite` `url` stays the bare origin: Google's site-names guidance says the domain home, and site names are not supported at the subdirectory level.
   - Fix the misleading comment at `:78-80`.
4. **Specs.**
   - Invariant specs per page: page addresses in the block equal `pageUrl` and the canonical; a language switch is followed; exactly one block; none on not-found pages.
   - Home asserts the identity URLs explicitly, without widening `pageAddressesIn`.
5. **e2e.**
   - `JSON_LD_PAGES` gains `/ur/hostels/lahore`.
   - Raw-HTML body tests for city, gender and campus on `ur`, plus `/ur` home.
   - A client-lane listing test (stubbed; it canonicalises to `/ur/hostel/1`).
6. **KB.**
   - `area/ssr-seo-and-prerender.md`: the identity exception and the SearchAction rule; remove the stale #202 line.
   - `area/search-and-discovery.md:35`: the landing breadcrumb is translated and prefixed.
