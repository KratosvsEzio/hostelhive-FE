### The ticket

The forgot-password page shows `err.message` verbatim, and hard-codes English strings, including developer copy: "Cannot reach the server — is the API running?". Users can hit:
- **a 422** "Otp already has been shared on your email. Retry after 10 minutes" on a second request within 10 minutes. #148's "Request new link" sends people here, so a double click lands on it;
- **a 500** for an unknown email (a backend bug), which would show Rails' or Angular's text.

**Fix (card):** mirror #148 and #149. Classify by status, plus the server text where needed; show translated keys in all 18 locales; never `err.message`; move the hard-coded strings into Transloco. Decide the copy for "a link was already sent" and for an unknown email, minding account enumeration ("prefer one neutral 'If an account exists, we've sent a link' message").

**Acceptance:**
- no raw server text, and every message translated;
- a repeat request shows a friendly "already sent" message;
- specs per status.

### What we already decided in this area

- **#148:**
  - pure classifier, translated keys, fail closed;
  - `inlineErrors()` on auth calls;
  - focus moves to the panel heading when a panel replaces the form;
  - per-attempt state keyed to the token.
- **#149:**
  - shared `core/errors/api-error-text.ts` (`errorStatus`, `serverText`, `isBareNotFound`);
  - a 403 is matched only on whole-word text;
  - focus goes to the error heading after a server failure, never for a local problem.
- **Copy:** no link lifetime in copy (#148 D7); titles reuse each locale's existing wording.

### Backend facts (BE `main` @ `3d00e0a`, read only)

- `forgot_password` (`sessions_controller.rb:85-95`):
  - `User.find_by(email: params[:email]&.downcase)`, then `user.id` **before** the nil check, so an unknown email is a **500** (`NoMethodError`);
  - a live invite (valid 10 minutes) gives **422** "Otp already has been shared on your email. Retry after 10 minutes";
  - otherwise it creates the invite, sends the email and returns **201** "We've sent an change password link to your email.";
  - the unreachable `else` would give a **404** "User does not exist" (enumeration).
- `rack_attack.rb`: throttle `user/forgot_password` at 5 per 5 minutes per IP gives a **429** `{"error":"Too many requests. Please try again later.","retry_after":N}`. The general limit is 150 per 5 minutes.
- An admin or moderator can request a link, but `reset_password` refuses it with a 403 (#148).

### FE facts

- `AuthApi.forgotPassword` already passes `inlineErrors()`, so there is no toast.
- `forgot-password.ts:30-32`: `emailError` is hard-coded English "Enter a valid email address.".
- `forgot-password.ts:58-65`: `fail()` maps 0 to developer copy, and everything else to `err.message`.
- **The resend error is never shown.** `error()` renders only inside `@case ('email')`, so a failed "Didn't receive it? Resend" in the `sent` phase (most likely the 422) shows nothing at all; the button just stops spinning.
- **The page has no spec file.**
- The `sent` copy is built from two fragments around the email (`weSentAPasswordReset` + email + `clickTheLinkInThe`), which is awkward to translate; it is existing.

### Understanding

Replace `fail()` with a classifier on the shared helpers:
- 422 "already shared" → a friendly "already sent" message;
- 429 → "too many requests";
- 404 or 500 → a decision is needed;
- 0 → network;
- anything else → generic.

Translate every string including `emailError`, show the resend error in the `sent` phase, and add the page's first spec. The open product question is what an unknown email should show, given the enumeration concern and the backend's 500.

### Staff Engineer report (condensed)

**Classifier:** `forgot-failure.ts` (new):
- 0 → `network`;
- 429 → `tooManyRequests`;
- a 404 whose text is not a bare "Not Found" → `noAccount`;
- a 422 whose text is not just "unprocessable entity" or "unprocessable content" (local constant) → `alreadySent`;
- anything else → `unknown`.

Built on `api-error-text.ts`; `message` is never read.

**Page:** `forgot-password.ts` / `.html`:
- `errorKey` and `noticeKey` hold translation keys, and `emailError` returns a key.
- **Send:** a 201 or `noAccount` goes to the sent screen; `alreadySent` goes there with the notice; anything else stays on the form with an alert.
- **Resend:** a 201 or `noAccount` shows "sent another"; `alreadySent` shows the notice; anything else shows an alert in the sent panel.
- **Clearing:** messages clear when a request starts, and the error clears when the email is edited.
- **Busy guard:** covers Send, Resend and "Use a different email", which stays disabled while a request is in flight so a late reply cannot land on the wrong panel.
- **Focus:** moves to the new heading on each panel swap (one-shot flag + `afterRenderEffect`). That includes back to the form heading after "Use a different email", which goes slightly beyond D7, because the focused button disappears.
- **Email in the body:** FSI/PDI-isolated and passed as a parameter.
- **Status region:** one `role="status"` region that is always present, between the heading part and the actions, using `empty:` utilities so it takes no space when empty.
- **Alert:** a `role="alert"` paragraph in both phases.
- **Heading:** the sent heading is `aria-describedby` the body and the notice.

**Translations:** 8 new `authForgotPassword` keys in 18 locales; `weSentAPasswordReset` and `clickTheLinkInThe` deleted (unused elsewhere). Each locale keeps its register, no digits. Every file was checked to round-trip byte for byte before writing.
