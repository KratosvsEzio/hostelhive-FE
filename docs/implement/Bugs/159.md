### The ticket

`core/interceptors/error-interceptor.ts` (`normalize`, about lines 273-282) sets `ApiError.message = serverMessageText(body) ?? Angular's message`. It does this deliberately, "because several screens render `err.message` inline". `util/models/api-error.ts` says the opposite: `message` may carry the API origin and path and must never reach a user.

Once nothing renders `message`, make it diagnostic only:
1. `normalize` sets `message` to Angular's message (or a fixed diagnostic); display text comes only from `serverMessages`, through classifiers and `toToastCopy`.
2. Rewrite `core/interceptors/error-interceptor.spec.ts` (about lines 69-95), which asserts the current behaviour.
3. Drop `serverMessageText` if nothing else uses it.
4. `util/subscription-error.ts` (about lines 38-41) reads `serverMessages` only.
5. Fix the comments in the interceptor and `util/models/api-error.ts`; the knowledge-base trap was already rewritten in #151.
6. Empty the error-read entries in `core/errors/no-raw-error-message.spec.ts`.

**Acceptance:**
- `ApiError.message` never contains server text; the specs are updated;
- the raw-message guard has no error-read allowlist entries left, and passes.

### What we already decided in this area

- **#148–#151:** every screen classifies through `core/errors/api-error-text.ts` and shows translated keys; nothing renders `message`. The guard enforces it with an exact allowlist.
- **The allowlist** holds 2 real error reads (#83's) and 5 non-error `.message` uses (billing `outcome`, `note`, `view`, `o`, `e`, and the notification invite), which stay.
- **#151 PE:** changing `message` before #83 lands regresses #83's screens from server text to Angular's URL text. This is why building is gated.

### Staff Engineer report (condensed)

- **Diagnostic:** `<METHOD> <pathname> → <outcome>`.
  - The pathname comes from `new URL(req.url, 'http://x').pathname`, so there is no origin, query or fragment. A fallback strips `?`/`#` and the origin.
  - The outcome is the numeric status, else the error's `name` (`TimeoutError`), else `error`. No `statusText`, never `undefined`.
  - Examples: `GET /api/x → 401`; `GET https://api.test/api/hostels/1/rooms?token=secret` gives `GET /api/hostels/1/rooms → 404`; the SSR timeout gives `GET /public/hostels → TimeoutError`.
- **Unchanged:** `status`, `code`, `serverMessages` and `method` (asserted).
- **`serverMessageText` deleted** (the interceptor was its only caller).
- **`isSubscriptionError`** reads `serverMessages` only; the raw `HttpErrorResponse` branch is kept.
- **Doc:** `api-error.ts` documents the diagnostic.
- **Guard:**
  - scans `features/`, `layout/` and `shared/`; keys are now relative to `app/`;
  - new allowlist entries `layout/components/toast-host/toast-host.html: 2` and `layout/components/notification-bell/notification-bell.html: 1`;
  - no new error reads were found.
- **Specs:**
  - the interceptor has a "diagnostic message" block (shape, origin and query dropped, no `statusText`, a 6×6 table of bodies × statuses, `TimeoutError`, no status or name);
  - `subscription-error` has the URL false positive and a bare 403 whose wording is only on `message`;
  - `host-builders` `apiError()` is diagnostic-shaped.
- **Pre-fix proof:** against the original three files, 45 tests fail (42 interceptor, 3 subscription). All older tests pass both ways; files restored and verified by hash. **Root cause: confirmed.**
- **Gates:** full suite in 3 shards, 72/1657 + 71/1528 + 71/1797 = **214 files / 4982 passed**; lint 0 errors; typecheck and i18n-check clean.
- **Not done:** about ten feature specs still build `message` as server text or Angular text. They are no-leak tests that still pass but no longer model the interceptor's output (a tidy-up follow-up). The D5 follow-ups are not here.

**Orchestrator re-check:** `serverMessageText` is gone from `apps/web/src`; `core` and `util` give 64 files / 1812 passed; `origin/main` is unchanged (685b88b).

## Summary

**Area:** API and data, the error contract. **`ApiError.message` is now a developer diagnostic `<METHOD> <pathname> → <status>`** (for example `POST /api/user/sign_in → 401`), built in `core/interceptors/error-interceptor.ts` (`requestPath`, `diagnostic`).
- It never contains server text, the API origin, the query string or `statusText`.
- A non-HTTP error such as the SSR `TimeoutError` gets its name in place of the status.
- `status`, `code`, `serverMessages` and `method` are unchanged, so toasts, billing, classifiers and host access behave exactly as before.

Also:
- **Removed** `serverMessageText` (`core/errors/api-error-message.ts`).
- **`util/subscription-error.ts`** classifies from `serverMessages` only, which removes a latent false positive on "subscri" in request URLs.
- **The raw-message guard** (`core/errors/no-raw-error-message.spec.ts`) now also scans `layout/` and `shared/`, with an exact allowlist of non-error reads: billing, the notification invite, the toast host, the notification bell.
