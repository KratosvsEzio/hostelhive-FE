### The cards

- **#132:** `Blog` calls `seo.apply` once, in its constructor (`blog.ts:174`), not in an effect. A client language switch (`/en/blog` → `/ur/blog`) reuses the component, so the head keeps the `/en/blog` canonical, `og:url` and hreflang. Home (`home.ts:80-88`), blog article and pricing apply inside an effect that reads the locale.
  - **AC:** on `/en/blog`, switch to Urdu: the canonical is `https://hostelhive.com/ur/blog` and the hreflang set is rebuilt.
- **#133:** `index.html:35` hard-codes `og:locale = en_PK`, and nothing updates it.
  - **AC:** the server HTML of `/ur/hostels/lahore` has an Urdu `og:locale`; `/en/...` keeps an English one.
- **#129:** only seven pages call `Seo.apply`: home, blog, blog article, listing, landing, search and pricing. After a client navigation from one of them to a page that doesn't (about, FAQs, careers, contact, legal, credits, auth, account), the previous page's canonical, robots and description stay.
  - **AC:** a client navigation from `/en/hostels/lahore` to a page without its own SEO leaves no Lahore canonical, robots or description.

### What the code shows beyond the cards

- **#129 also has a server-render half.** A page that never calls `apply` is served with `index.html`'s defaults, including `<link rel="canonical" href="https://hostelhive.com/">`. So `/en/about`, `/en/faqs` and `/en/contact` canonicalise to the **home page** in the HTML crawlers read. That is the #131 shape, on indexable pages. Their `og:url` is the home page too, so a shared `/en/about` link previews as home. Not reproduced yet; see Reproduction.
- **Pages without `apply` set their title through the route** (`app.routes.ts`, `title:` on about, FAQs, pricing, careers, contact, privacy, terms, service policy, credits, confirm, reset, account pages, notifications, forbidden). These titles are English literals. There is no custom `TitleStrategy`.
- **`og:locale` is the only per-language Open Graph slot.** `Seo.apply` already knows `locale.active()`.
- **`LOCALES`** (`core/i18n/locales.ts:61-80`) has 18 codes, all `translated: true`.

### Understanding

#132 moves `Blog`'s `apply` into a locale-reading effect. #133 adds `og:locale` (and possibly `og:locale:alternate`) to `Seo.apply` from the active language. #129 needs **every** route to end up with a head that describes it: either each page calls `apply`, or a router-level default fills in for pages that don't. That decides what happens to `index.html`'s static tags. All three are head-only, and server-render `curl` plus client-navigation e2e can verify them.

## Plan

### Merged plan

1. **#129, route-level head (the PE's option a).**
   - New `core/route-head.ts`: `RouteHeadStrategy extends TitleStrategy`, provided in `app.config.ts`. Route data `head: 'page' | 'index'` sits on parent routes in `app.routes.ts`:
     - `'page'`: the component calls `Seo.apply` itself. Home, search, both landing routes, hostel, pricing and blog.
     - `'index'`: a static page that should be indexed. About, FAQs, careers, contact, the three legal pages and credits. Each may have an optional `descriptionKey`.
     - **No data: `noindex`, with no canonical and no `og:url`.** Auth, account, consoles, notifications, forbidden.
   - `updateTitle` keeps setting the route title synchronously (GA reads it). It sets a `pending` signal; a root `effect` gated on `locale.ready()` applies the default head and re-runs on a language switch. Routes marked `'page'` get only the title.
   - A route-table spec keeps the sitemap and the route data consistent.
2. **`index.html`:** remove the canonical, `og:url` and `og:locale`. Keep the description, robots, og/twitter title, description and image, and the app links, as the fallback before boot and for client-only shells.
3. **#132:** Blog's `apply` moves into a `ready()`-gated effect (the `home.ts` pattern), which also stops the route title from overwriting Blog's title.
4. **#133:** a required `ogLocale` on `Locale` (`locales.ts`) for all 18 codes; `Seo.apply` writes `og:locale`. No `og:locale:alternate`.
5. **Sitemap:** add `/pricing`, and `/credits` if it is indexable.

### Principal Engineer (key content)

- **Mechanics:**
  - The router order is as above; `LocaleStore.switchTo` sets `active` before navigating.
  - Every page except Blog applies in an effect, and `apply` reads `locale.active()`, so those effects already re-run on a switch.
- **Rejected options:**
  - **(b) a navigation-scoped "claimed" flag.** A query-only navigation on a reused page re-runs no page effect, so the default overwrites a correct indexable head. `switchTo` also races `NavigationStart`.
  - **(c) every component calls `apply`.** That is about 45 components and 70 route entries, and it cannot express "noindex by default".
  - **An `ActivationEnd` or `ResolveEnd` hook.** Constructors have already run, and `ResolveEnd` is skipped on some navigations.
  - **Applying synchronously in `updateTitle`.** The new language's strings may not have loaded yet.
- **Edge cases:**
  - Default → page and page → default.
  - A language switch on a default route.
  - Query-only navigations.
  - A guard redirect lands on auth's noindex head.
  - Server render: the effect runs before the app is stable.
  - `<head>` is not hydrated, so tags are updated in place.
  - GA still reads the title synchronously.
  - A `'page'` route missing its flag is harmless, guarded by the consistency spec.
  - The English-only legal pages match the sitemap today (follow-up).
  - #138 is partly mitigated if default routes clear JSON-LD.
- **Requirements 1–8:**
  1. One owner of the head per navigation.
  2. Indexable static pages: server and client both have their own canonical, `og:url`, 19 hreflang and robots index.
  3. Routes without data: noindex, with 0 canonical, `og:url` and hreflang.
  4. `og:locale` follows the active language everywhere; no alternate.
  5. `index.html` has no canonical, `og:url` or `og:locale`.
  6. The blog switch works, and `/en/blog`'s server title is Blog's own.
  7. The title is set synchronously.
  8. Sitemap and route data agree.
