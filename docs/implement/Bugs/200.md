## Ticket understanding

**Source manifest:**
- Trello card #200: ready. I filed it today from the #139 QA review.
- Code: ready.
- KB: `area/public-content.md`, and `area/ssr-seo-and-prerender.md` (the route-title rule "Prefer a label the page already uses").
- `context-gatherer` was not spawned: the card, the one file and the one key were all read directly.

**The ticket.** `layout/components/site-footer/site-footer.html:45` renders the footer's "Image credits" link as a literal English string. Its siblings (`footer.privacyPolicy`, …) go through `| transloco`, so on every non-English URL this one label stays English. The comment above the link explains why: the locale files were mid-edit in another branch when it was added, and the label "wants translating once they are free".

**What already exists.** `routeTitle.imageCredits` ("Image credits") is the `/credits` route's title key (`app.routes.ts:108`). It is present and translated in all 18 locale files (e.g. ur "تصاویر کے کریڈٹس", ar "حقوق الصور", de "Bildnachweise"), and `route-title-locale-parity.spec.ts` gates its presence in all 18.

**Acceptance (from the card):** the `/ur` footer shows the Urdu label and `/ar` the Arabic one; the key is present in all 18 locale files; a footer spec asserts the label goes through the translation key.

## Root cause

**Status:** confirmed. The hard-coded literal and its own explanatory comment are at `site-footer.html:43-45`.

| | |
|---|---|
| **Symptom** | The footer's "Image credits" link reads English on `/ur`, `/ar` and every other language. |
| **Cause** | `apps/web/src/app/layout/components/site-footer/site-footer.html:45` is a text literal, not `'…' \| transloco`. It was added while the locale files were locked in another branch (the comment at :43-44), and the follow-up never came. |
| **Why it escaped** | `i18n-check` finds keys, not literals, so an English string in a template is invisible to it, and there is no footer spec. A component test asserting the label is a key would have caught it. |
| **Same shape elsewhere?** | Not in the footer: every other link label there is a key. Other raw English in templates is a known, separate trap (maps popups, `area/i18n.md`), outside this ticket. |

## Plan

**Merged plan:** replace the literal with `{{ 'routeTitle.imageCredits' | transloco }}` and replace the stale "English for now" comment with one saying why the page's title key is reused. No locale file changes. Add a footer spec (none exists) asserting that every footer link label is a translation key, which catches this literal and any future one.

**PE and PM were not spawned** (see Notes): the change is one template token, using a key that already exists and is already spec-gated. The orchestrator did the analysis directly against the code above.

**Risks:**
- The footer label and the page title are now one string, so changing one changes the other. That is intended (the link names the page it opens).
- `TranslocoPipe` is already imported by `SiteFooter`, so no `.ts` change is needed.

### Independent verification (5d)

`qa-reviewer` verdict: **coverage sufficient**. No implementation defects, and no other hard-coded English in `site-footer.html` (headings, tagline, copyright and social `aria-label`s all go through `| transloco`). Run: 2 files, 167 passed.

**Findings and what was done:**
- **Should-fix, now fixed: icon-only links skipped the key check.** TC-02 filtered out links with no text, so the four social links were never checked, and a literal `aria-label` could have slipped through. Now, for a link with no text, TC-02 checks its `aria-label` instead, and a link with neither fails. Mutation check: replacing `[aria-label]="'footer.instagram' | transloco"` with `aria-label="Instagram"` fails with `expected [ 'Instagram' ] to deeply equal []`. The file was restored and verified with `cmp`.
- **Nit, now fixed: the key regex was too strict.** It rejected valid key shapes such as `common.2026HostelhiveAllRights` and three-level keys. Now `/^[a-z][A-Za-z0-9]*(\.[A-Za-z0-9_]+)+$/`.
- **Nit, not taken: pin the link count to 11.** That would break whenever a link is added, for no gain in what this test is for. `> 0` already stops an empty result from passing.
- **Note: the social links point to `href="#"`.** They are placeholders, outside this ticket, and recorded here only.

After the fixes: `site-footer.spec.ts` passes, 2 of 2.
