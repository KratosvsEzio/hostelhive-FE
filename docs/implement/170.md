## Ticket understanding

Source manifest: Trello card (ready, read in full with its 2026-10-18 status comment); repo code (ready). No design, no contract — none needed.

The card's status comment (2026-10-18) records that PR #136 already translated the `hostBookings` and `hostInvoices` keys and added `core/i18n/host-ops-locale-parity.spec.ts`. The parity spec this card asks for therefore exists; the work is to extend it.

Still open:
- `booking-details-panel.ts`: `ACTION_LABEL`, the lane hints, `requestedAgo`, `askedFor` / `askedForDetail` (plurals).
- `booking-details-panel.html`: section labels (Stay, Quoted, Due, Booked, In rooms, Reason, Contact, Payment), room-list states, Release / Releasing…, "Room N · N guests", Paid / At the property, still due / Nothing outstanding, Close, the `'Booking'` fallback, "Requested … · via …".

- `hostRooms`: 7 keys are English-only in all 17 other locales (`nFree`, `full`, `guestsOnBookings`, `noBookingGuests`, `guestCount`, `untilDate`, `couldNotLoadBookingGuests`), and the parity spec does not cover the group.
- Specs asserting English text must move to keys.

The card's branch `i18n/host-bookings-translations` does not exist (checked 2026-10-31).

Also on the page but not named by the card: the table column headers (`util/table-configs/host-bookings-table-cols.ts`), the filter labels (`util/filter-configs/booking-filter-groups.ts`), the calendar lane labels (`booking-month.ts` `LANES[].label`) and "Awaiting confirmation" / "Confirm" in `booking-calendar.html`, and the pager's "N bookings" (the shared `lib/src/ui/lib/data-table`, used app-wide).

Plurals: the app has no plural rules; a count picks a `…One` key when it is 1 (`count-singular-locale-parity.spec.ts`).

## Plan

Planned by the orchestrator directly. The ticket is a mechanical copy move; the analysis (strings, existing keys, conventions) is above. No PE/PM agents were spawned, which is recorded under Notes.

1. Move every hard-coded string on the page to `hostBookings.*` keys, reusing `common.*` where one already says the same thing.
2. Lane names become keys (`LANES[].labelKey`). Templates pipe them; the filter options and the table read them through a translate function the page supplies, which the page rebuilds when the language's strings load (the `injectAdminBillingCellFormat` pattern).
3. Status badges (panel, dialog, table) show the lane's translated name; the server's `disposition.name` is the fallback for an unknown slug.
4. `requestedAgo` uses `Intl.RelativeTimeFormat` in the active locale.
5. Translate the new keys and the 7 English-only `hostRooms` keys into all 17 other locales.
6. Extend `host-ops-locale-parity.spec.ts` with `hostRooms`; add the new pairs to `count-singular-locale-parity.spec.ts`.
7. Move the specs from English text to keys.

## Implementation

Branch `claude/170-host-bookings-i18n-ef50bd` (the app's worktree branch, contains `origin/main` 1a66d1c0). Done by the orchestrator in one pass, with no fan-out: the copy moves touch the same few files, so splitting them would only have created collisions. Translations went to four parallel agents (ur/hi/ar/fr/de, es/it/nl/da, sv/hu/pl/ru, id/vi/ja/zh), each writing a scratch JSON fragment that was merged by a parse-add-write script. The merge round-trips byte-identically (2-space JSON, CRLF, trailing newline) and only appends to the `hostBookings` / `hostRooms` groups.

Translator notes kept as decided:
- Same as English on purpose: "Status" (de, nl, sv, pl, id `filterStatus`), "via {{source}}" (nl, sv, da), Danish "Booking" / "Reference", Dutch "Details". `filterStatus` and `viaSource` are kept out of the must-differ list; the rest are named exceptions in the parity spec.
- Polish and Russian plain count keys use the genitive plural, matching `common.nNights`. Where a count's grammar would break, the sentence was rephrased as "label: {{count}}".
- Danish `noRoomsToCheckInto` says "Dette sted" rather than the file's "ejendom".
