Logged-in hosts pass their hostel's country; visitors send none (backend uses the request country, defaults USD). Each card: name, monthly price, Listing / Boost / CRM checklist.
- **2. Billing screen:** `GET /api/hostels/:id/billing` → `currency, country_code, payment_methods, subscription (null before first purchase), features, open_invoice, plans (each with action, amount_due_now)`. Current plan card: name, status badge, renewal date (`current_period_end` in `hostel.timezone`). Payment-due box when `open_invoice`: number, amount, what it is for, expiry, **Pay** (→ card 3/8); `awaiting_verification` → "Bank transfer under review".
- **3. One button per plan by `action`:** `buy` "Choose plan" → checkout · `current` "Current plan" disabled · `renew` "Renew" → checkout · `upgrade` "Upgrade: pay {amount_due_now} now" + "renews at {price} on {current_period_end}" → checkout · `downgrade` "Switch at renewal" (card 5/8) · `unavailable` disabled, showing `reason`.
- **4. Checkout:** `POST /api/hostels/:id/checkout {plan_id}` → 201 `{invoice}`; then open the payment step (card 3/8) with that invoice. 422 "Set the hostel's country first" → link to the hostel edit form.
- **Acceptance:** PKR for a PK hostel, USD for non-PK · billing screen shows current plan, status, renewal date, payment-due box · right button per action, upgrades show `amount_due_now` · Buy/Renew/Upgrade call checkout and open the payment step with the returned invoice · 422 messages shown as returned.

#### 2. Knowledge base

**Warning:** `area/host-billing-and-subscription.md` still describes the legacy model and the unmerged-backend plan. It is stale after #94, and the "Pending" marker is wrong now. #94 deferred updating it. The code wins.

Points that bear on #95:
- **Money:**
  - `MoneyPipe` (`shared/currency/money.pipe.ts`) takes a number or numeric string, so `"5000.00"` works.
  - It rounds to 2 places, shows 0 decimals for a whole amount and 2 otherwise, and formats with `Intl.NumberFormat` in the active `LocaleStore` locale.
  - It renders only the number. The symbol comes from `currencySym` (`currencySymbol(code)` in `util/currencies.ts`).
  - Symbols are `PKR` → `Rs` and `USD` → `$`. The card's example is "PKR 5,000" and "$18", so a PKR format needs a decision (code prefix versus the `Rs` symbol).
  - `money-decimals-follow-the-amount.md` is an Accepted decision: use `money` for every displayed amount.
  - Do not use `formatAmount` or `formatPriceCompact`; they ignore the language and group with `en-PK`.
- **Dates:**
  - `apiDate` (`util/api-date.ts`) formats a timestamp in the offset the string carries, e.g. `| apiDate: 'dd MMM yyyy'`. It uses `LOCALE_ID`, which is always `en-US` here.
  - `render-api-timestamps-in-their-own-offset.md` is Accepted. The backend serialises in its own offset, so "renewal date in `hostel.timezone`" is largely handled by the offset in the string.
  - If an explicit zone is needed, `util/zoned-time.ts` (`zonedWallTimeToUtc`, `localDateAtWallTime`) and `util/time-zones.ts` exist, but the KB says `zoned-time.ts` is dead code outside its spec. There is no existing "format an instant in zone X" helper.
- **ApiClient (`core/api-resource.ts`):** `get(path, params, context?)`, `post(path, body, context?)`, `put`, `patch` and `delete(path, body?)`. Services are one per area and re-exported from `services/index.ts` as `@services`.
  - Response envelope: `{...payload, success:true}`. Errors are `{success:false, errors:[…]}`.
  - Obfuscated ids are used as returned. The KB warns embedded raw integers do not compare with them, so key by slug or name.
  - Status objects are `{id,name,slug,color}`: branch on `slug`.
- **How 422 errors surface:**
  - `errorInterceptor` normalises every failure to `ApiError {status, code, message, serverMessages?, method}` and re-throws it. `message` is the server text when the body is an envelope.
  - A global pinned toast fires for every 4xx except 401. It joins `serverMessages` and truncates to 200 chars. A screen that shows the error inline must pass `SUPPRESS_ERROR_TOAST` (an `HttpContext` token from `core/tokens.ts`) or the user sees it twice.
  - Matching on the message text is the only option for "Set the hostel's country first", because the body flag `country_required` is dropped by the interceptor.
- **Gate component:** `<hh-subscription-gate>` (`layout/components/subscription-gate/subscription-gate.ts`) is a paywall card with hard-coded English benefits and a "View plans & subscribe" link to `/host/{selected}/subscription`. It stays.
- **Public pages:**
  - Routes sit as flat siblings in `LOCALISED_ROUTES` in `app.routes.ts`. `about` is at line 79 and `faqs` at 85, each a `loadComponent` with a `title`.
  - The tree is mounted twice, under `:locale` and bare.
  - `app.routes.server.ts` renders everything not listed as `RenderMode.Server`; only `''` is prerendered. `host`, `admin` etc. are client-only. So a `/pricing` route is server-rendered by default, with no entry needed unless you want it prerendered.
  - Public static pages bring no console shell: `App` shows `SiteHeader` and footer.
- **Host page chrome:** `DashboardLayout` (`app-dashboard-layout`, `[label]`) for every console page title bar and scroll area. `hhContainer` is for public page width. `hostNav()` is the single source for sidebar and More. `hostPagePath()` is for URL arithmetic.
- **UI library:**
  - Reuse `hh-button` (never a hand-styled `<button>`), `hh-card`, `hh-status-pill` (tones `ok|warn|danger|neutral`, optional dot), `hh-skeleton`, the `states/` components, `hh-badge`, and `hh-confirm-modal`.
  - `hh-status-pill` is the status badge. It maps tone, not the API `color`, so the mapping from `status.slug` is app code.
  - Icons come from the subsetted Tabler font. Run `npm run icons:font` when adding a `ti-*` class.
- **i18n:**
  - Keys are `group.key` camelCase, with `{{name}}` parameters. Add new keys to `en.json` (the only gated file) **and** the other 17 files, or they silently render English.
  - `i18n-check` finds literal keys by regex.
  - Locale files are CRLF on disk. Parse and `JSON.stringify(…, null, 2) + '\n'`, written back as CRLF.
  - `publicOnboarding` payment keys: #94 kept 14 of them for #96 to reuse.
- **Traps:**
  - `afterNextRender` never fires in this zoneless app. Use `ngAfterViewInit`.
  - The hostel id comes from the URL, and `HostPropertyStore.selected` is only a store mirror. Use `activeHostel()`, or pass the route id to guards.
  - In `host-console.md`, "Invoices" means renter bills, not HostelHive billing invoices.

#### 4. Backend contract (`azeem-hamza/hostelhive@main`)

**Routes** (`config/routes.rb`):
```ruby
scope 'hostels/:hostel_id', controller: :hostel_billing do
  get :billing, action: :show
  post :checkout
  get :invoices
  post 'subscription/schedule_downgrade', ... ; delete 'subscription/schedule_downgrade', ...
  post 'subscription/cancel', ... ; delete 'subscription/cancel', ...
end
resources :invoices, only: [:show] do post :payments, on: :member, action: :create_payment end
resources :plans, only: [:index]
```
These sit under `namespace :api`.

**`GET /api/plans`** (`app/controllers/api/plans_controller.rb`):
```ruby
skip_before_action :authenticate_user!
country = params[:country].presence || request.headers["CF-IPCountry"].presence
currency = Billing.currency_for_country(country)
render_success_response({ currency: currency, country: country&.upcase, plans: plans }, :ok)
```
- It is **public**.
- `country` accepts any string; `PK` (case-insensitive) gives `PKR` and anything else gives `USD`. `Billing.currency_for_country` is `country_code.to_s.upcase == "PK" ? "PKR" : "USD"` (`app/services/billing.rb:19-21`).
- With no param it uses the `CF-IPCountry` header. A visitor with no header gets USD, and `country` is null in the response.
- Plan shape from `Billing::Summary.plan_prices_json` (`summary.rb:22-26`): `{ id, code, name, features, interval, currency, price }`. `price` is nil when the plan has no price in that currency.
- `features` holds add-ons only, `boost` and/or `crm`. Listing is implicit in every plan.

**`GET /api/hostels/:hostel_id/billing`** (`hostel_billing_controller.rb:13-16`, `summary.rb:10-19`): returns `{ billing: {…}, success }`.
```ruby
{ currency:, country_code: @hostel.country_code, payment_methods: HOST_PAYMENT_METHODS.fetch(currency, []),
  subscription: subscription_json, features: @subscription&.features || [],
  open_invoice: open_invoice_json, plans: [...with action...] }
```
- `subscription` is `nil` when there is no subscription, or when it has no plan (`summary.rb:39`). Otherwise `{ id, status:{id,name,slug,color}, currency, plan:{id,code,name,features}, current_period_start, current_period_end, grace_until, scheduled_plan:{id,code,name}|nil, cancel_at_period_end }`.
- `open_invoice` is `nil` if none or expired. Otherwise `{ id, number, kind, total, currency, period_start, period_end, expires_at, awaiting_verification }`. `total` is a decimal string, `kind` is `new|renewal|upgrade`. The payload has no plan name for the invoice (the checkout `invoice` does have `plan`).
- `payment_methods` is `["safepay","bank_transfer"]` for both PKR and USD (`billing.rb:17`).
- `features` is a subset of `listing|boost|crm`.
  - Boost counts only while `active`.
  - Listing and CRM stay on while `past-due` (`subscription.rb:27-36`).
- **The billing payload has no timezone.** `HostelSerializer` includes `timezone`, `country_code`, `has_crm` and `accepts_bookings` (`hostel_serializer.rb:4-7`).
- Subscription status slugs: `incomplete|active|past-due|expired|canceled`. The status object has no `possible_statuses` here.

**Plan `action` enum and `reason`** (`summary.rb:67-80`):
```ruby
return { action: "downgrade", amount_due_now: nil, scheduled: @subscription.scheduled_plan_id == plan.id } if quote[:downgrade]
return { action: "unavailable", amount_due_now: nil, reason: quote[:error] } if quote[:error]
action = if !live? then "buy"
         elsif quote[:kind] == "upgrade" then "upgrade"
         elsif @subscription.past_due? then "renew"
         elsif plan.id == @subscription.plan_id then "current"
         else "renew" end
{ action: action, amount_due_now: Billing.to_major(quote[:total_minor]) }
```
- The full set is `buy`, `upgrade`, `renew`, `current`, `downgrade`, `unavailable`.
- `reason` exists **only** on `unavailable`. It is the `quote[:error]` text, e.g. "This plan is not available", "This plan is not available in USD" or, for a non-live hostel with no country, "Set the hostel's country first".
- `downgrade` also carries `scheduled: bool`.
- `current` has `amount_due_now` = the renewal price, not zero. The card says the button is disabled and shows "Current plan".
- `upgrade`'s `amount_due_now` is the prorated whole unit (`checkout.rb:77-84`), and the label's "renews at {price}" is the plan's own `price`.
- Note: a hostel with no country and a non-live subscription gets `unavailable` with "Set the hostel's country first" on **every plan**, not just on checkout.

**`POST /api/hostels/:hostel_id/checkout {plan_id}`** (`hostel_billing_controller.rb:18-22`, `checkout.rb`):
- `render_success_response({ invoice: Invoice.serialize_json(invoice) }, :created)`.
- `Plan.active.find(params.require(:plan_id))`: an unknown plan gives 404 (inferred from `find`) and a missing param is probably 400.
- It reuses the open invoice if kind, plan, currency and total match. Otherwise it voids the old one and issues a new one. If a bank transfer is awaiting verification it raises "A bank transfer for invoice HH-… is waiting for verification".
- 422 messages (`checkout.rb`):
  - `Set the hostel's country first` (line 38)
  - `This plan is not available`
  - `This plan is not available in #{currency}`
  - `Choose a cheaper plan by scheduling it for your renewal`
- Authorisation is CanCan `authorize!(:create, @hostel.invoices.new)` (line 10), and a failure is 403.
- Invoice shape (`app/serializers/invoice_serializer.rb:4-6`): `id, number, kind, currency, total, period_start, period_end, expires_at, paid_at, voided_at, created_at, invoice_pdf_url, plan{id,code,name,features}, lines[{description,amount}], status{id,name,slug,color}, payments[]`. Invoice slugs are `open|paid|void`.
- The card's list `{id,number,kind,currency,total,status,lines,plan,expires_at}` is a subset of this.

**422 envelope** (`billing_access.rb:6-8`, `render_message_template.rb:11-17`):
```ruby
rescue_from Billing::Error do |error|
  render_error_response({}, :unprocessable_entity, [error.message])
end
# → { errors: [msg], success: false }, status 422
```
- 403 from CanCan has a different shape: `{ success: false, error: "<msg>" }` with the **singular** `error` key (`api_controller.rb:19-22`).
- 404 is `{errors:["Requested resource not found."], success:false}`.

**Pay step (for the #96 seam)** (`invoices_controller.rb:14-21`):

#### Data flow and state

##### Loading the billing screen
`hostelId = toSignal(route.parent!.parent!.paramMap → 'hostelId')`. Then, following the house pattern in `hostel-profile.ts:89-101`:

```
state = toSignal(toObservable({id, refresh}).pipe(
switchMap(id => api.billing(id).pipe(map(ok), startWith(loading), catchError(err → error(err))))))
```

- `switchMap` cancels an in-flight load when the host switches hostel.
- The state carries `{loading, data, error: ApiError|null}`.
- `refresh` is bumped after checkout errors that change server state, and is the hook #98 uses (its endpoints return the full `billing`, so #98 can also set the data directly).

##### Checkout
- One component signal, `pendingPlanId = signal<string|null>(null)`.
- While it is non-null, **every** checkout-capable button is `[disabled]`, and the clicked one is `[loading]` (`hh-button` has `loading`, `button.ts:131`). That is the double-click guard. The server's `with_lock` and invoice reuse make a duplicate harmless anyway.
- **Success (201):** `router.navigate([... 'subscription', 'pay', invoice.id], { state: { invoice } })`.
- **Error:** set `checkoutError = { planId, message: err.serverMessages?.[0] ?? fallback, countryRequired }` and render it inline above the plan grid in a danger-tone block.
- `countryRequired` is `message === "Set the hostel's country first"`. The body flag `country_required` is dropped by the interceptor, so the text is the only signal.
- When `countryRequired`, append a link to `/host/:id/profile`, shown only when `can('host:Hostel:show')`.
- For the 422 "A bank transfer for invoice … is waiting for verification", also bump `refresh` so the payment-due box shows "under review".
- **403** → the inline message "You don't have permission to buy plans for this hostel" (the server's singular `error` arrives in `serverMessages`).

#### Dates and timezone

Finding (hypothesised from source, to be confirmed live at 5e):
- `HostelBillingController` includes only `BillingAccess` (`hostel_billing_controller.rb:3-4`), not `HostelTimeZone`.
- `config/application.rb:19` leaves `config.time_zone` at its UTC default.
- So `current_period_end`, `grace_until`, `expires_at` and the period dates serialise as **`…Z` (UTC)**, not in the hostel's offset.
- Periods are instants (`Time.current + Plan::INTERVAL`, `checkout.rb:41-42`). For a PK hostel, anything bought between 00:00 and 05:00 PKT renders `apiDate` **one day early**.
- `expires_at` is a 24-hour TTL (`billing.rb:13`), so the time of day matters there and is wrong by 5 hours.

Options:
1. **Backend one-liner (recommended):** add `include ::HostelTimeZone` to `HostelBillingController` **after** `before_action :load_hostel`, following the ordering in `hostels_controller.rb:3-5` (the around_action needs `@hostel`). Ideally do the same in `InvoicesController`, with `@hostel = @invoice.hostel` set in `load_invoice`. Timestamps then arrive as `+05:00` and `apiDate` is correct unchanged, consistent with the accepted decision "render API timestamps in their own offset". This is a change in another repo, so it is Q4.
2. FE fallback: fetch `HostelsApi.getForEdit(id)` for `timezone` and format with `Intl.DateTimeFormat({timeZone})` in a new helper.
 - It costs an extra request per load.
 - `/edit` is CanCan `edit`-gated, so a manager with billing access but not hostel-edit access would lose the date.
 - It duplicates `apiDate`.
 - Only worth doing if the backend refuses.
3. Accept UTC. Not recommended for `expires_at`.

Either way, the FE writes `| apiDate: 'd MMM yyyy'` (and `'d MMM yyyy, h:mm a'` for `expires_at`). With option 1 nothing else changes.

6. **Given** a plan with `price: null`, **then** it is left off the pricing page.
7. **Given** a visitor (logged out, or logged in without a host role), **then** every card has one CTA, **List your hostel**, which goes to `/host/listings/new`. The auth guard handles login.
8. **Given** a logged-in host with a selected hostel, **then**:
 - the page requests plans for that hostel's country code;
 - every card's single CTA is **Go to billing**, which goes to `/host/{selectedId}/subscription`.

 If the hostel has no country code, the page falls back to the visitor request (no `country` parameter).
9. **Given** any response, **then** a line under the heading names the currency:
 - USD: "Prices in US dollars. Hostels in Pakistan are billed in PKR."
 - PKR: "Prices in Pakistani rupees."
10. **Given** the plans request fails, **then** an error state with Retry appears, never an empty grid.
11. **Given** an RTL locale (ar or ur), **then** the layout mirrors, and the amount and currency stay together as one unit, not split by bidi reordering.

##### B. Billing screen: loading, errors and access

12. **Given** a host opens `/host/:id/subscription`, **then** the screen calls `GET /api/hostels/:id/billing` and shows a skeleton until it answers.
13. **Given** the billing request returns 403, **then** an inline "no access" state appears. No toast fires (`SUPPRESS_ERROR_TOAST`).
14. **Given** a network or server error, **then** an inline error with Retry appears, with no duplicate toast.
15. **Given** the nav, **then** a **Billing** entry with icon `ti-receipt` goes to `/host/:id/subscription`:
  - on the sidebar and on the mobile More page (`hostNav` and the `more.ts` tint);
  - after a divider (the "account" group that `splitNav` was kept for).

##### C. Current plan card

16. **Given** `subscription: null`, **then** the card reads "No plan yet" with "Choose a plan below to list your hostel on HostelHive". There is no badge, no date and no button.
17. **Given** a subscription, **then** the card shows `subscription.plan.name`, a status badge labelled with `status.name` from the API and toned by `status.slug`, and a date line chosen by status:

| slug | badge tone | date line |
|---|---|---|
| `active` | ok | "Renews on {current_period_end}" |
| `active` with `cancel_at_period_end: true` | ok | "Ends on {current_period_end}" (never "Renews") |
| `past-due` | warn | "Payment was due on {current_period_end}", plus "Pay by {grace_until} to keep your listing" when `grace_until` is set |

| `expired` | danger | "Ended on {current_period_end}" |
| `canceled` | neutral | "Ended on {current_period_end}" |

19. **Given** any date on this screen, **then** it shows as `dd MMM yyyy` and represents the hostel's local calendar date (see rule R4).
20. **Given** the features list, **then** the card shows which of Listing / Boost / CRM are active now, from `billing.features` and not from the plan. This is how past-due correctly shows Boost off.

##### D. Payment-due box

21. **Given** `open_invoice` is null, **then** there is no box.
22. **Given** `open_invoice` is set, **then** a box above the plans shows:

  - the amount (`total` + `currency`, formatted per rule R1);

    - `upgrade`: "Upgrade charge · {period_start} – {period_end}"

23. **Given** `awaiting_verification: true`, **then** the box keeps the number, amount and purpose, replaces Pay with a status pill reading **Bank transfer under review**, and shows "We'll update this page once our team confirms your transfer." No date or SLA is promised.
24. **Given** Pay is clicked, **then** the host goes to the payment-step seam with that invoice id (see section 5, Q1).
25. **Given** an unknown `kind`, **then** the purpose line shows the period only.

#### 4. Product rules to respect

| # | Rule | Source |
|---|---|---|
| R1 | **Never compute money.** Show the API decimal string with its own `currency`. PKR shows as the code plus a space ("PKR 5,000"); USD uses the symbol ("$18"). Whole numbers have no decimals; others have two. Use `MoneyPipe`, not `formatAmount` or `formatPriceCompact`. The app-wide `currencySymbol('PKR')` gives "Rs", so billing needs its own display rule, or the card's example is broken. | Card ground rules; `apps/web/src/app/util/currencies.ts:15`; `docs/knowledge-base` decision money-decimals-follow-the-amount |
| R2 | The currency belongs to each amount (`plan.currency`, `open_invoice.currency`, `invoice.currency`), not only to the page. | Card ground rules; `summary.rb` |
| R3 | Currency is decided by the server: PK gives PKR, everything else gives USD. The frontend sends a country but never chooses a currency. | `billing.rb:19-21` |
| R4 | The renewal date is shown as the hostel's calendar date. The billing payload has no timezone; `HostelDetail.timezone` (`util/models/hostel.ts:149`) does. Unless the PE shows that the backend serialises in the hostel's offset, the date must be shown in the hostel's timezone, or a period ending near midnight shows the wrong day. | Card section 2; context report section 5 |
| R5 | One primary CTA per card: one button per plan, one Pay in the payment-due box, one CTA per pricing card. | Card section 3 |
| R6 | Branch on `status.slug` and `action`, never on `status.name` or ids. Ids are obfuscated and used as returned. | Card ground rules |
| R7 | 422 `errors[0]` is shown as returned, in English, in every locale. `reason` follows the same rule. | Card ground rules |
| R8 | Listing is in every plan. `features` lists add-ons only (`boost`, `crm`). | Live `/api/plans` payload |
| R9 | Past-due keeps Listing and CRM but drops Boost, so the screen's features come from `billing.features`. | `subscription.rb:27-36` |
| R10 | Checkout reuses or voids the open invoice; the server handles this. The frontend does not warn or block, and the box is refreshed after checkout. | `checkout.rb` |
| R11 | Public plans: there is no auth, `country` is optional, and the result is USD when no country can be found. | `plans_controller.rb` |

#### 7. Product risks

- **P1. The payment step is a stub until #96 lands.** Each Choose plan click before #96 creates a real open invoice that nobody can pay online. **Recommendation:** ship #95 and #96 to production together, or accept the Contact-us stub. The invoices this creates are harmless: the server reuses or voids them.
- **P2. The timezone is missing from `/billing`.** A host could see a renewal date one day out. See R4 and Q5.
- **P3. Untranslated text.** Server strings (`reason`, 422 messages, plan names, `status.name`) appear in English in all 18 locales. The ground rules accept this, but ur and ar hosts will see mixed-language cards.
- **P4. Matching on English text.** The country link depends on matching the exact English message "Set the hostel's country first", because the interceptor drops the `country_required` flag. If the backend changes the wording, the link silently disappears. Pin it with a test.
- **P5. A free-text country.** The hostel form takes the country as free text (`hostel-form.html:400`). A host who types "Pakistan" may still be billed in USD if the backend's `country_code` derivation fails. #95 cannot fix this; it only shows the currency honestly on every amount.
- **P6. Staff access is unverified.** The frontend has no permission constant for billing (`core/auth/roles.ts:42` types Permission as a free string), so the staff experience can't be confirmed before QA.
- **P7. Server-rendered currency on `/pricing`.** On the server render, the `CF-IPCountry` header the API sees is the SSR server's, not the visitor's. Every visitor could get the server's currency (probably USD). **Recommendation:** fetch plans in the browser only (show a skeleton on SSR), or forward the visitor's header.
- **P8. Two reasons for a PK host to see USD.** A PK host who opens `/pricing` while logged out, or with no country set, sees USD. The currency line (AC 9) explains this.
