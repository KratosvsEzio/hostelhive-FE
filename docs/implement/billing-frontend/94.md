#### C. The gate question

`SubscriptionStore.isActive` is `contract()?.status === 'active'`, and the contract comes only from `current_subscription` (`subscription-store.ts:29`). With the endpoint gone, a request to it would 404 or fail. The store would then end in `status 'error'` with `contract` null, so `isActive()` is always false.

| Consumer | Today | If the endpoint is removed and the store is left in place |
|---|---|---|
| `host-shell.ts` `runSubscriptionGate` and `enforceGate` (:140-186) | Bounces to `/host/:id/subscription` unless the route is exempt. | **Every non-exempt page bounces to a route that no longer exists.** Hosts are locked out of the whole console. |
| `host.routes.ts` `createHostelGate` (:83-98) | Redirects to `/host/${id}/subscription` when not active. | **Hosts with a hostel can never open `/host/hostels/new`.** |
| `bookings.ts:416` | `lapsed` is true when `status()==='ready' && !isActive()`. | The banner never shows, since the shell exempts `bookings` and never loads the store. |
| `booking-form-drawer.ts:350` | `isSubscriptionError(e)` on the create response, from the server. | Not affected by the store. |
| The six paywall pages | `isSubscriptionError(err)` on their own request errors. | Not affected by the store. They depend only on server error text. |

So the whole store and gate chain must be removed or replaced in #94. It cannot be left in place.

Two things to decide:
- **Remove all client gating in #94** and rely on the server's own rejection: the paywall pages, the booking drawer and `isSubscriptionError`. Card 5/8 would then rebuild gating on `/api/hostels/:id/billing`. This matches the acceptance criterion that no request goes to `/current_subscription`.
- **Stop the redirects to the removed routes.** That is `bounceToSubscription`, `createHostelGate`, `new-hostel.ts:71` and the `routerLink`s in `bookings.html:18`, `booking-form-drawer` and `subscription-gate`. The `<hh-subscription-gate>` component has a link to `/host/:id/subscription`, so its callers also need a target. I did not read its template.

The `OPEN_WHILE_LAPSED` decision becomes moot once the store goes. That is a decision-file change worth recording.

#### 3. Edge cases and risks

- **R1: lapsed hostels now see error toasts on pages without an inline paywall** (team, expenses, mess, profile, more). Before, the gate bounced them away and muted toasts. Now a server 400 "You need to subscribe" toasts on those pages. This is accepted under the settled assumptions (#99 adds the banners); mention it in the PR.
- **R2: a stale hostel list can bounce the post-create landing.**
- `knownHostelGate` (`host.routes.ts:140`) decides from the cached list without refetching when it is loaded and non-empty.
- A host who already has hostels and creates one through onboarding or `hostels/new` would land on `/host/<newId>/subscription`, find the new id missing from the cached list, and be sent to `/host`, which opens the old hostel's overview.
- Onboarding never passed this gate before, so the onboarding case is a new regression. In `hostels/new` the same staleness already exists today.
- Fix: call `HostPropertyStore.load()` just before `router.navigate`. `load()` sets `loaded` to false (`host-property-store.ts:137`), so the gate waits for the fresh list.
- **R3: onboarding where `refreshSession` fails.** The wizard swallows the error (`onboarding-wizard.ts:763`) and navigates anyway. The new target sits under `host`, which has `roleGuard(...HOST_ROLES)`. The old payment route only needed `authGuard`. A first-time host whose refresh failed would be turned away by `roleGuard` instead of seeing the payment page. This is rare, and a reload recovers it. Accept and note.
- **Removed URLs:**
- `/host/listings/new/payment`: `host/listings/new` loads `ONBOARDING_ROUTES`, which has only `''`, so `payment` doesn't match. Under `host`, `:hostelId=listings` has no `new` child. It falls to `**` and goes home.

- There is no 404 page, as already settled.
- **SSR:** `app.routes.server.ts` lists no removed paths (`host` and `admin` are client-only by prefix). No change needed.
- **Lazy chunks:** the onboarding payment lazy chunk disappears. The host and admin chunks shrink because their pages were static imports. Nothing prefetches by chunk name (grep).
- **Permissions:**

### Product Manager report (verbatim)

### Product framing for Trello #94: remove the old order, contract and host-payments flow

#### Problem and intent

The backend has replaced the old products / orders / contracts billing model with plans, billing and invoices (PRs #26–#28, all merged). The frontend still calls five endpoints that no longer exist, so some screens are broken. Worse, the host console's client-side subscription gate reads `current_subscription`. Once that call fails, every host would be bounced to the subscription page, and hosts who already have a hostel could not create another one.

###94 is a clean-up ticket. It removes every caller of the old endpoints and their screens, and it leaves one valid page at `/host/:id/subscription` for #95 to build on. It must not change anything a host or admin does that isn't billing. Its success shows up as a lack of breakage: no failing network calls, no lock-outs, no dead links.

#### Affected parties and impact

| Who | What they notice |
|---|---|
| **Host with an active plan** | The 2-second "checking subscription" overlay disappears and the console opens straight away. The "Subscription" and "Payment history" menu items are gone. |
| **Lapsed or unsubscribed host** | They are no longer bounced to a page. They can open any page, and the server decides what is allowed. The six paywalled pages still show the "Unlock …" card. Its button now leads to a placeholder that says buying a plan is coming soon. |
| **New host (onboarding or "add hostel")** | After saving, they land on the new hostel's billing placeholder instead of the fake payment page. Nothing is lost: `pay()` was only a `setTimeout` stub (`onboarding-payment.ts:142`). |
| **Admin** | `/admin` and the account-menu "dashboard" link now open Payments instead of Contracts. The Contracts nav item is gone. |
| **Anyone with an old bookmark** | They are sent to the home page (see Q1). |

#### Acceptance criteria

**Network**

1. A source search for those paths returns no hits, except in specs that assert they are absent.

**Menus and routes**

2. Given a host on any hostel, when they open the sidebar, the mobile nav or the "More" page, then neither a "Subscription" nor a "Payment history" item appears, and no empty divider is left where they were.
