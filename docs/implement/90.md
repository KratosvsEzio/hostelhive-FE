## Ticket understanding

The card was written on 2026-10-04, before #94 and before payments were paused. It asks for two things:
1. Offset-aware `dayRangeStartLocal` / `dayRangeEndLocal` on admin and moderator date filters, for example admin contracts `f[end_date]` and payments `f[created_at]`.
2. Admin and moderator timestamps shown in the viewer's zone, or labelled UTC.

A comment after backend PR #24 says list endpoints now return hostel records in each hostel's offset. Records with no hostel come back in UTC. Admin and moderator filters still use UTC days.

### What the code shows today (main @ 4116bac4)
- **Filters.** The only admin or moderator date filter is admin billing `f[created_at]` (payments and invoices, `services/admin-billing-api.ts:79-80`), sent through `dayRangeStart`/`dayRangeEnd`. #94 removed admin contracts, and `admin-api.ts` and `moderation-api.ts` have no date filters.
- **Billing display.** Billing renders through `adminUtcDate` with the note "Dates are in UTC". That is a recorded decision (`decisions/dates-money-and-time-zones/admin-billing-dates-in-utc.md`), and it is the card's own "label UTC" alternative.
- **Other admin and moderator dates.** Admin listings (`admin-listings.ts:305`), roles (`admin-roles.ts:356`), and moderator review, queue and member-since (`moderation-api.ts:389,476,481`) and media (`media.ts:503`) format with `date-fns` `format(parseISO(iso))`. That already renders in the viewer's zone. The moderator audit screen reads fixtures only.
