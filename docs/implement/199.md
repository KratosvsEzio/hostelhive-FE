## Ticket understanding

Source manifest: Trello card (ready), `docs/implement/Bugs/193.md` (ready), `docs/knowledge-base/area/host-billing-and-subscription.md` (ready), backend `app/controllers/api/host/host_controller.rb` on `azeem-hamza/hostelhive@main` (ready, read-only).

The card: after #193, `isSubscriptionError` is true only for the 400 "You need to subscribe…" and a defensive 402. The plan lock (`hostAccessInterceptor` → `deriveAccess` → `<hh-access-lock>` in place of the router outlet) already owns that 400 for non-admins. So two plan surfaces have no live audience, and both hold hard-coded English:
- `<hh-subscription-gate>` on overview, rooms, tenants, utilities, add-bill and invoices (`BENEFITS`, "View plans & subscribe");
- the booking drawer's renewal notice ("This hostel's subscription has lapsed…", "Renew subscription"), whose link also closed the drawer and dropped its fields.

Decide: retire both and rely on the lock, or translate them into 18 locales with a staff variant.

Acceptance: no hard-coded English on these surfaces; a plan refusal is explained once (the lock), never twice or falsely; specs updated.

### Does the lock cover every case the gate covers?

Checked in code before putting the choice to the user.

| What the gate caught | Lock? | Evidence |
|---|---|---|
| 400 "You need to subscribe…" for a non-admin | **Yes** | `classifyHostAccess` (`core/host-access/host-access.ts`) records it as `inactive` for any `/api/host/hostels/:id[/…]` URL. Every one of the 7 callers uses such a URL (overview `overview_cards`, rooms, renters, utility_bills, renter_bills, add-bill's three, drawer `POST …/bookings`). `deriveAccess` sets `bodyLock: 'offline'` for non-admins, and `host-shell.html` swaps `<router-outlet>` for `<hh-access-lock>` on every CRM section, which includes overview, rooms, bookings, tenants, utilities and invoices (`CRM_SECTIONS`, `host-nav.ts`). The page and any open drawer are destroyed in the same render. |
| The same 400 for an admin | Not needed | `deriveAccess` never locks for admins, but the backend never sends it to them: `is_hostel_active?` and `require_crm!` both `return if current_user.admin?` (`host_controller.rb`). |
| A 402 | **No** | `classifyHostAccess` ignores it. No backend source for a 402 is known. |
| Any other non-403 whose text matches `subscri`, `upgrade.*plan`, `plan.?required` | **No** | Same; the KB already notes nothing sends one. |

After retiring, the two uncovered cases fall to each surface's existing generic error: `hh-error-state` with Retry on the six pages, `hostBookings.couldNotSaveBooking` in the drawer. That is the card's "generic error for the rare case the lock doesn't engage".

## Plan

Retire (user's decision, see Decisions).
1. Delete `layout/components/subscription-gate/` (component and spec).
2. Six pages: drop the `subscriptionError` view state, the gate branch and its import; a caught load error is always `error: true`. Drop the `[disabled]="state().subscriptionError"` header bindings on rooms, tenants and invoices.
3. Booking drawer: drop `needsSubscription`, `subscriptionLink`, the renewal block, and the now-unused `RouterLink` / `LocaleLink` imports. A plan refusal goes through `bookingSaveFailureKey` like any other failure.
4. Delete `util/subscription-error.ts` and its spec: nothing calls it any more, and it was the twin classifier the KB warns drifted once (#193).
5. Drop the `subscriptionGate` block from all 18 locale files (round-tripped).
6. Test helpers: `LoadSurface` loses `'paywall'`; `inactive` and `paymentRequired` now expect the generic error.
7. KB: `area/host-billing-and-subscription.md`.

## Notes

### Live verification is not possible for the retired surfaces

The gate and the renewal notice only rendered on a backend refusal for a hostel with no live plan (or a 402 nothing sends). Producing one on staging would mean lapsing a hostel's plan, which is billing work, paused since Safepay was dropped (2026-10-31). The behaviour is pinned by component specs instead.
