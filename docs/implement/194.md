## Ticket understanding

Source manifest: Trello card (ready, full text incl. the #193 scope update; no comments); repo code at `origin/main` d5d66f2c (ready); `docs/implement/170.md`, `199.md`, `187.md` (ready).

The card (code-proven on 8ebfaf0, not seen live) lists what still mis-describes a permission 403 after #187 and #193:
1. **Opening a booking** — `bookings.ts` `followUrl` reads a 403 as "We couldn't find that booking"; the open re-read (`reread`) swallows it.
2. **The bookings list and calendar** — a 403 on load shows the generic error.
3. **Invoices "Mark paid"** — the global toast "Not allowed" with the server's English.
4. **Save / edit / delete 403s** on rooms, tenants, utilities and invoices.
5. **Add utility bill in edit mode** — loading the bill (`editError`).
6. **A 400 "offline" (no live plan) on stay moves** — reads as `moveNotAccepted`.
7. **The global toast on a 403 GET** — shows the server's English beside the page's own message.

Fix direction: reuse `isPermissionRefusal` / `isCrmRequired` (`core/host-access/host-access.ts`); action keys `hostBookings.notAllowed` / `notAllowedOwner` / `planHasNoCrm`; pages that fail to open use `hostAccess.pageNotAllowed(Owner)` via `<hh-permission-refused>`. Translated, once, no server text.

Already on main and reused: `testing/backend-refusals.ts` (every refusal body, run through the real interceptor), `testing/load-refusal-surface.ts` (reads which surface a page renders), the rooms/tenants/utilities/invoices/add-bill/overview list-load panels (#193).

Payments are paused: the invoices Mark paid change is error copy only; no payment flow is exercised.

## Root cause

**Status: confirmed** — a mutation run (refusal key removed from the shared toast, plan-inactive branch removed from the stay-move keys) failed 41 of the new tests across 4 files; restored, all green.

| | |
|---|---|
| **Symptom** | A host user whose role lacks a permission sees "We couldn't find that booking", a generic load error, "Not allowed: You are not authorized to access this page." or "The server did not accept that" instead of being told they lack permission. |
| **Cause** | Each surface classifies its failure locally and none asks `isPermissionRefusal`: `bookings.ts` `followUrl` (status 0 vs everything-else-is-not-found), `bookings.ts` `state` and `booking-calendar.ts` loads (`catchError(() => error: true)`), `invoices.ts` `markPaid`/`markBoth` and the delete handlers (`toToastCopy`, which echoes server text), the save handlers (one fixed key each), `add-bill.ts` edit load (boolean), `booking-move-failure.ts` (no 400 subscribe branch). |
| **Why it escaped** | Specs per page cover the generic failure only; the refusal-kind table (`backend-refusals.ts`) arrived with #193 and has only been applied to list loads. |
| **Same shape elsewhere?** | Yes — team, hostel-profile, room-detail, tenant-profile, expenses, the overview detail pages and billing also render a generic error on a 403. Out of scope here; listed in Notes. |

## Plan

Planned by the orchestrator from the code read above (no PE/PM agents: the card names every surface and the fix direction, and #187/#193 settled the rules; recorded in Notes).

1. Shared (done first, alone): `core/host-access/host-access.ts` gains `isPlanInactive`, `actionRefusalKey(err, {owner})` (CRM → `hostBookings.planHasNoCrm`, permission → `hostBookings.notAllowed(Owner)`, else null), `pageNotAllowedKey({owner})`, `planInactiveKey({owner})` (→ `hostAccess.offline` / `offlineStaff`). `<hh-permission-refused>` uses `pageNotAllowedKey`. `services/host-ops-api.ts` list/save/delete methods take `opts?: ApiRequestOptions`.
2. Every surface asks `actionRefusalKey` (writes) or `isPermissionRefusal` → panel / `pageNotAllowedKey` (reads) before its own fallback. Non-permission failures keep their current copy.
3. Writes the page reports itself go quiet (`suppressErrorToast`); the page's own toast/inline line is the one message.
4. Loads whose page draws its own error state go quiet (D1).
5. Stay moves, room release and the cross-pay invoice: a 400 "need to subscribe" → `planInactiveKey`.
6. No new locale keys.
